# 發車看板「我的地點」人工驗收

這份清單專門驗 iOS 小工具設定畫面。DynamicOptionsProvider 是否真的被 iOS 呼叫，只有「主畫面加小工具 → 長按 → 編輯小工具 → 點各欄位」能證明；App 本體或命令列 harness 成功都不能取代。

## 0. 測試前準備

1. 用本批修改後的 App 安裝到 iPhone 或 Simulator，先開啟一次，等地圖與列車載入完成。
2. 若出現定位權限詢問，本功能不依賴定位，可依測試需要選擇；不要把「定位」誤當成「儲存地點」。
3. App 內點「更多」→「儲存地點」，在台鐵／高鐵站附近點地圖落釘。
4. 在地點卡點「存」，名稱輸入「家」，再點「儲存地點」。至少再存一筆「公司」。若要驗空名稱，第三筆名稱留空直接儲存。
5. 每次儲存後等至少 1 秒；WebView 會在 `rail-user-data-changed` 後 debounce 500ms，再把整份地點寫成 App Group 根目錄的 `places.json`。

## 1. 起站選單

1. 回主畫面加入「軌島」的「發車看板」小工具。
2. 長按小工具 →「編輯小工具」→ 點「起站」。
3. 最上方應先看到 section 標題「我的地點」，後面才是「基隆市、臺北市……」等縣市段。
4. 地點列的 title 應是使用者名稱，例如「家」；空名稱必須顯示「未命名地點」。
5. subtitle 的完整格式應像「台鐵 竹北 · 1.2 公里」；未滿 1 公里時應像「台鐵 竹北 · 420 公尺」。系統名、站名與距離要和實際落釘位置一致。
6. 離所有有座標車站超過 5 公里的地點不應出現；同一車站若有多個地點，只應留下距離最近的那一筆；整段最多 20 筆，手動存的地點排在 Google Takeout 匯入地點之前。

## 2. 跨段重複值（本批必量、不可用推論代替）

1. 在「我的地點」點「家」（假設它解析到 `tra|竹北`）。
2. 返回設定頁，確認起站欄位已顯示「家」或其對應選取狀態，桌面小工具不再停在「請選擇起站」。
3. 再打開起站選單，分別觀察「我的地點」裡的「家」與「新竹縣」裡的「竹北」：
   - 兩列是否都出現勾選；
   - 只有第一列勾選；
   - 只有縣市列勾選；
   - 或清單出現跳回、無法選取、值被清空等異常。
4. 把實際結果記下。若跨 section 重複值確實破壞選單，下一批才採 plan B：被地點認領的車站從原縣市段移除；本批沒有預先實作 plan B。

## 3. 目的站選單

1. 先選好起站，再點「目的站（可留空）」。
2. 若「家／公司」對應車站在該起站的 `destinationOptions(from:)` 可直達集合內，「我的地點」應出現在最前面，列格式與起站相同。
3. 對應車站沒有直達列車的地點不可出現；若所有地點都不可直達，整個「我的地點」section 不應出現，既有縣市段仍須正常。
4. 清除或更換起站後，再打開目的站，確認目的站清單會跟著可直達集合更新。

## 4. 判斷欄位是否被 iOS 停用

點起站或目的站那一列後，立刻在 Mac 執行：

```bash
xcrun simctl spawn booted log show --last 30s --predicate 'process == "RailBoardWidgetExtension"'
```

有新的 extension 活動才代表 iOS 真的詢問 provider。完全零活動表示那一列在 AppIntents 層就被停用；不可把「畫面沒反應」誤判成 provider 回傳空清單。

## 5. 舊檔與壞檔人工抽驗（可選）

- 把 App Group 的 `stations.json` 換成沒有 `la`／`lo` 的 v2：起站仍應列出全部 256 個車站並分成 19 個縣市段，只是不顯示「我的地點」。
- 依序讓 `places.json` 不存在、內容為 `{}`、內容為壞 JSON：三種情況都應照常打開完整起站清單，只是不顯示「我的地點」。
