# 出新 build 的規則

> 2026-08-23 立。起因：1.4.9 (75) 上架後才發現它比 1.4.8 (68) **少了一整批功能**——
> 一顆合併（`63e38b2`）把 `index.html` 整檔取了 main 那一側，凡「只活在 App 線、沒併進 main」
> 的內容當場全部消失。build 成功、archive 成功、既有 verify 全綠，**沒有任何一道閘門會紅**。
> 這份規則就是為了讓同一種事故下次一定會被擋在上傳之前。

## 一、每顆 build 出貨前必過的四道

1. **`npm run verify`（含出貨回歸閘門）**
   `app/scripts/verify_no_ship_regression.mjs` 已接進 `verify-release.mjs`，出貨鏈上自動跑到。
   它比對七類識別字（函式／元素 id／更新紀錄 `data-cl`／說明中心節 key／方案面板功能項／
   旗標常數／URL 參數），基線是 `app/shipped-baseline.json`。
   **紅了不准改基線放行**，三條出路寫在腳本的錯誤訊息裡。

2. **確認這顆的 version train 還開著**
   ASC 只讓「短版本字串等於版本紀錄版號」的 build 被選進去，**已上架的 train 會被回絕**。
   線上現行版號用帶 no-cache 的 lookup 實查（裸 URL 會拿到 CDN 舊值）：

   ```bash
   curl -s -H 'Cache-Control: no-cache' "https://itunes.apple.com/lookup?id=6792673516&t=$(date +%s)" | python3 -c "import sys,json;d=json.load(sys.stdin)['results'][0];print(d['version'], d['currentVersionReleaseDate'])"
   ```

   線上版號 == 你要掛的行銷版號 ⇒ **那個 train 已關**，必須進位（例：1.4.9 已上架 ⇒ 改開 1.4.10）。
   這件事要在**打包之前**查，不是打完才查。

3. **「更新了什麼」有寫**
   `set-release-mode.mjs` 的 `why` 同時是 App Store What's New 與 App 內彈窗。
   ⚠️ 既有閘門只檢查 why 裡有沒有**行銷版號**，所以「marketing 不動、只升 build 號」時它擋不住
   忘改 why——那種形狀要自己看一眼。

4. **build 號只進不重用**
   一個 build 號只能對應一份載貨。作廢的 archive 就讓它作廢，**不要用同一個號重打**——
   「同號兩份不同內容」正是這整串事故最難查的地方。

## 二、基線什麼時候可以推進

**只有在那一顆真的上傳成功之後**：

```bash
node app/scripts/verify_no_ship_regression.mjs --update \
  --from <上一顆已上架的 index.html>,<這一顆的 index.html> \
  --marketing <版號> --build <build 號>
```

`--from` 要給**所有還在使用者手上的 build**（不是只有最新那顆）。
08-23 丟掉的正是「68 有、75 沒有」——只拿 75 當基線的話，那次損失連被發現的機會都沒有。

## 三、合併進 App 線之前

`index.html` 在 App 線與 main 線都會被改，而且**兩邊的內容不是彼此的超集**。
合併時：

- **絕不整檔取單邊**（`git checkout --theirs/--ours <檔>`、或把衝突檔直接複製過去）。
  判斷方法：合併完 `git diff <合併結果> <被併掉那一側>` 若為空，就是整檔取單邊了。
- 三方比對用 `git merge-file --diff3`，衝突逐一手裁。
- 合併後跑一次出貨回歸閘門（`node app/scripts/verify_no_ship_regression.mjs --cand index.html`），
  它會直接列出被吃掉的識別字。

## 四、既有 verify 的一個結構性弱點

`verify_plus_ctas.mjs` 與 `verify_boot_geo.mjs` 從 08-22 起就一路紅——**但它們不在出貨鏈上**，
沒有人會在出 build 的時候跑到，所以紅了三天沒人看見。
⇒ 新寫的驗收腳本若涵蓋「使用者看得到的功能」，就要嘛接進 `verify-release.mjs`，
要嘛接進每日巡檢；放在 repo 裡等人想到才跑 == 沒有這支腳本。
