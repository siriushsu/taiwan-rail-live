# 林鐵推進／牽引方向修復

2026-09-13 查核。適用本線、神木、沼平與動態祝山班次的常態運轉示意；不宣稱取得當班機車調度紀錄。林鐵的節數仍是三節示意，本次不增加車長。

## 查核依據

- [鐵道專家蘇昭旭〈任重道遠半世紀 阿里山的柴油機車〉](https://trainworld.site/2011/12/%E4%BB%BB%E9%87%8D%E9%81%93%E9%81%A0%E5%8D%8A%E4%B8%96%E7%B4%80-%E9%98%BF%E9%87%8C%E5%B1%B1%E7%9A%84%E6%9F%B4%E6%B2%B9%E6%A9%9F%E8%BB%8A/)：機車通常朝嘉義端，上山推、下山拉。這是車輛方向的基本依據；不可忽略之字形折返而直接按海拔判斷。
- [林業署山林悠遊網：林業軌道](https://recreation.forest.gov.tw/Railway/Introduce)：列出第一分道、第二分道、神木、阿里山四處之字形爬升點，說明方向變換時推進與牽引會交換。
- [鐵道局 110 年林鐵定期檢查報告](https://www.rb.gov.tw/public/upimgs/A00/111/110%E6%9E%97%E9%90%B5%E5%AE%9A%E6%9C%9F%E6%AA%A2%E6%9F%A5.pdf)，頁 19：2021-09-30 實地乘車查察記錄，阿里山往神木是推進運轉，車長在前方守車、機車在後方。
- [鐵道局事故事件公告 111-001](https://www.rb.gov.tw/public/upimgs/A00/111/%E9%90%B5%E9%81%93%E5%B1%80%E4%BA%8B%E6%95%85%E4%BA%8B%E4%BB%B6%E5%85%AC%E5%91%8A111-001%28%E6%9E%97%E9%90%B51015%29.pdf)：阿里山往神木推進，神木往二萬平牽引。這份為工程列車紀錄；旅客線方向另以上一份實地查察交叉核對，不把工程車編組套給客車。

## 模型與方向

舊程式每班初始 `formationFacing=1`，等於不分來向先把機車放在最前端；雖然遇到來源路徑折返會翻轉，初始端已錯。本次按首段所屬路線設定機車所在端，再乘既有經道岔與站名驗證的折返次數。以站序決定，沒有用車次奇偶、地理南北或瞬間坡度猜測。

| 行駛區間 | 機車位置 |
|---|---|
| 嘉義向第一分道 | 後端推進 |
| 第一分道向第二分道 | 前端牽引 |
| 第二分道經二萬平向神木 | 後端推進 |
| 神木向阿里山 | 前端牽引 |
| 阿里山向沼平、祝山 | 後端推進 |
| 上述各段反向 | 前後互換 |

神木→阿里山為爬升卻是牽引；阿里山→神木為下降卻是推進。因此不能用「上坡時把火車頭倒過來」處理。沼平／祝山沿共用出口及其常態上山方向推定，沒有當班機車調度來源；此部分是明列的路線示意推論。

既有 renderer 以 `formationFacing` 同時決定每節車的位置、車體朝向、前後燈與車頭柔光，故沿用同一欄位，沒有只交換外觀而讓燈光仍倒著。整列中心、班表、路徑與 hold 均不修改。非林鐵的初始方向仍為 1。

新線或未辨識起點回傳 null，維持既有顯示，不能把它當成已核實方向。驗收會要求目前完整林鐵名冊均可辨識；改點或新增路線時須更新查核。這次修正在實體路徑模式生效，舊版 `tracks=legacy` 除錯模式不在本次方向保證範圍。

## 驗收

`node scripts/verify_afr_push_pull.mjs` 在 Chromium 與 WebKit 讀取實際載入的 50 班靜態車及 97／98 動態觀日班次，檢查 16 個獨立列出的方向案例、實際 DL25 模型首末節里程、雙向之字形折返、四種手機寬度的觸控操作。整趟每 30 秒比較修前／修後中心及車身出現狀態，避免方向改動造成車輛消失。

來源路徑端點原已有短暫車身裁切與交接隱藏；測試逐筆比較修前同時點，不把既有裁切冒稱已修復。六次折返均檢查方向交換，來源線形能容納整列的四次另量每節車在邊界的位移；其餘兩次保留原有裁切限制，不能宣稱所有折返全程可見。

本輪結果：兩引擎各 52 班、2,530 個完整車身取樣，16 個方向案例均符合預期；六次折返方向交換正確，四次可見整列的邊界最大車廂位移小於 0.000001 m。手機 360／375／414／768 均完成觸控切換地形。既有 `verify_afr.mjs` 為 138 過／0 敗；編組、台鐵既有改派連續性、執行期快取與更新紀錄檢查通過。將初始方向突變回 1，第一個嘉義上山案例立即失敗，沒有改動產品控制組。
