> 純讀碼＋離線重放，未改任何產品檔、未部署、未動 git。
> 實測樣本：正式站 `https://railisland.tw/api/trtc-live` 兩次快照
> `/tmp/trtclive.json`（`boardPos.at` = 10:17:40）與 `/tmp/trtclive2.json`（10:28:56）。
> 本目錄腳本：`replay_shift.mjs`（逐字重放前端算式）、`exp_binder.mjs`（冷啟動 vs 現況受控實驗）、
> `exp_ref_lock.mjs`（ref 鎖死實驗）、`slot_error.mjs`（綁錯幾個班表槽位）。

## 一句話結論

**1069/1611/1744 秒不是誤點，是「綁錯班次」。** 車實際上準點（把每台車配到時刻最貼近的
班表班次，殘差中位數 28 秒，89 台裡只有 2 台超過 120 秒）。後端逐班綁定器把整條線的車
系統性地綁到「早 k 個班距」的那一班，k=1~3；shift ≈ k × 該線班距，前端原封不動照抄。

## 可複現的具體算式（10:17:40 那一輪，逐 byte 對得上 payload）

### A. 中山國小的 407 號車（新莊線 dir1）

官方列（`boardPos.rows`）：`{no:"407", line:"O_XINZHUANG", dir:1, from:9, to:8, run:96, arrEpoch:1786933167}`
→ `arrSec = 37167`（10:19:27），`depSec = 37167 − 96 = 37071`（**10:17:51 離開中山國小**）

被綁到的班次 `20@33960>0@36817`（迴龍 09:26 發）在中山國小的表定發車 = **35460（09:51:00）**

```
shift = depSec − scheduledEvent = 37071 − 35460 = 1611   ← payload 的 shift 就是 1611
前端 rawArrivalSec = 35460 + min(runBetween(9→8)=96, span) = 35556
     visualShift   = arrSec − rawArrivalSec = 37167 − 35556 = 1611
```

**同一時刻，班表上真正對得起來的那一班是 `20@35580>0@38437`（迴龍 09:53 發），
它在中山國小的表定發車 = 37080（10:18:00）；shift = 37071 − 37080 = −9 秒。**
也就是這台車準點到 9 秒以內，卻被算成誤點 1611 秒。

### B. 迴龍站的起點列（terminal，最乾淨的一筆）

官方列：`{line:"O_XINZHUANG", dir:1, from:20, to:20, terminal:true, arrEpoch:1786933324}` → `arrSec = depSec = 37324`（10:22:04）
被綁到 `20@35580>0@38437` → `tr[1] = 35580`（09:53:00）

```
shift = 37324 − 35580 = 1744    ← payload 的 shift 就是 1744
正確答案：20@37320>0@40117（迴龍 10:22:00 發）→ shift = 37324 − 37320 = 4 秒
```

注意 B 佔走的正是 A 該用的那一班 → 這是一條連鎖佔用鏈。

### C. 使用者 09:50 量到的 1069 秒

新莊線 dir1 班表班距 = **540 秒**。`1069 ≈ 2×540 − 11`（早 2 個槽位），
`1611 ≈ 3×540 − 9`（早 3 個槽位），`1744 ≈ 3×540 + 124`。
09:50→10:17 之間正好多掉一個槽位。（此條為推算：沒有 09:50 的 payload 快照可重放。）

## 為什麼會漂、又為什麼回不去（三個互相加強的機制）

1. **候選搜尋是單向的**（`ledger:1141`，`TRIP_BIND_MAX_EARLY_SEC = -90`）：
   綁到「較晚的班次」會得到負 shift，早超過 90 秒就被禁早發擋掉；綁到「較早的班次」
   得到正 shift，卻可以到 +600（相對 ref）／+1800（絕對）。實例：BR dir2 某車最貼近的
   班次 shift = **−126**（被禁早發擋掉），退而求其次的前一班 shift = **+150**，於是綁前一班。
2. **一班只能被一台車佔**（`ledger:1122` `occupiedTripKeys`）：鏈頭錯一格，後面每台車發現
   自己該用的班次被佔，只能往前一班拿 → 整條線集體位移。B 案例正是鏈頭。
3. **錨點與判準同源，於是鎖死**：
   - `ref` = 同 line|dir、20 分鐘內綁定的 `lastShift` **中位數**（`ledger:1006-1015`）。
   - 出生 cost = `|shift − ref|`，上限 600（`ledger:1143-1144`）。新莊線 dir1 的
     ref = median(1611,1656,1708,1744) = **1682**（偶數取中間兩筆平均，`ledger:109-114`）
     ⇒ 準點候選的 cost = `|−9 − 1682| = 1691 > 600`
     **⇒ 一台準點的車在結構上不可能綁回正確班次**。
     實驗 D（`exp_ref_lock.mjs`）：把 407 的綁定拿掉、連正確班次也讓出來，407 仍然
     `UNBOUND`，audit `capped=1`。
   - 安全閥比的是 `|lastShift − ref|`（`ledger:1017-1023`），兩邊同源 ⇒ 群體性偏移下恆為 0，
     `evictedSafety` 永遠不會觸發（B 實驗 audit 實測 `evictedSafety:0`）。
   - 無反轉約束比的是「各自加上自己 shift 後的發車時刻」（`ledger:1059-1074`），
     整群同量偏移時完全看不出反轉。

## 前端的三個放大器

1. **中位數退路不是被離群值污染，是整群都錯**（`index.html:17321`、`17904`）：
   `_trtcBoard.all = trtcMedian(matched 的 visualShift)`。新莊線九筆全在 534–1744，
   中位數 1611 ⇒ 沒配到看板的車也一起被拖 1611 秒。這條路徑本身沒有算術錯誤。
2. **easedShift 不會製造大值，但會扣住它**（`index.html:16788-16793`）：
   下降速率 = `adv × (maxRate − 1)`，而 `metroRateCap()`（`index.html:5328`）對新莊線
   算出 `maxRate = 1.3394` ⇒ 每模擬秒最多消掉 0.339 秒偏移，
   **就算 target 立刻歸零，1611 秒也要 79 分鐘才走得完**（各線：BR 70、R 81、G 82、
   O_LUZHOU 59、BL 72、Y 81 分鐘；G_XBT/R_XBT 約 29 分鐘）。
   例外：有 endpoint motion 時 `index.html:17871-17873` 會直接寫入 `cur = visualShift`（雙向瞬移），
   `gateEpoch` 改變時也會 snap（`16785`）——所以它是「慢放」不是「永久鎖」。
3. **位置公式的夾限把車堆在起點**（`index.html:5274`）：
   `shifted = clamp(tr[1], tr[末], rosterTime − sh)`。t = 37060、sh = 1611 ⇒ shifted = 35449，
   而 dir1 這三班的發車秒 35580 / 36120 / 36720 全都 > 35449 ⇒ **一起被夾在 tr[1]，
   三台車同時畫在迴龍**。這就是使用者看到的「被畫回起點、跟後車疊死」。

## 已排除（附證據）

- **秒 / 毫秒混用**：沒有。全鏈唯一的 epoch→秒轉換在 `trtcServiceSec()`，重放逐 byte 對上 payload。
- **跨日 / 跨午夜**：沒有。`trtcServiceDayOfEpoch` 04:00 切日、`trtcMotionServiceSec` ±43200 折返，
  本輪 10:17 離切點極遠；冷啟動實驗用同一套函式得到中位 21 秒。
- **班表相位錯 / 班表過期**：沒有。本機 `data/trtc_times.json`、`data/trtc.json` 與正式站
  md5 完全相同（`3bd0262…` / `13e4a18…`）；班表位置與官方位置逐站吻合；冷啟動綁定殘差中位 21 秒。
- **中位數被少數極端值污染**：不是。九筆值全部落在 534–1744，整群一起錯，median 忠實反映該群。
- **easedShift 記憶化 / gateEpoch 把一次性大值鎖住**：不是病因。它每幀追 target，
  epoch 變化與 endpoint 路徑都會直接對齊；它只讓「修好之後」回不快（見上）。
- **真的誤點**：不是。同一批觀測配到最貼近班次的殘差中位數 28 秒（10:17:40）／31 秒（10:28:56），
  89 台裡只有 2 台 > 120 秒。

## 修法方向（未實作，供裁示）

1. **ref 不可自我參照**：出生 cost 的錨點改成「與班表的絕對距離」或用外部量（例如同線
   官方回報的實際班距），不要用自己這群 `lastShift` 的中位數；否則錯一次就永遠自洽。
2. **搜尋要雙向**：禁早發（−90）是為了防「提早發車」的假配對，但它同時讓
   「稍微早到」的正確候選出局。改成對稱窗（例如 ±½班距）並用「最小 |shift|」而非
   「最接近 ref」決勝。
3. **安全閥要用不同源的判準**：例如「本車 shift 與同線同向**班距**的比值接近整數」＝疑似錯配，
   或直接偵測「整群 shift 同時 ≈ k×班距」。
4. 前端 `visualShift` 大於某個門檻（例如 ½ 班距）時，寧可 unbound（回純班表）也不要照抄——
   位置錯 27 分鐘比沒有校正更糟。
