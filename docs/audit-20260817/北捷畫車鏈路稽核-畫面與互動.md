## F1（P0）純班表模式下誤點校正仍在生效 → 列車整批往回彈（＝使用者說的「倒退跑」）

**意圖**：`metroLiveOn()` index.html:16946
`if (TRTC_PURE_SCHEDULE_POSITION && isTrtcBoardLine(ln)) return false;`
⇒ `metroShiftSec()` 17321 的 `if (ln._trtcBoard && on)` 不成立 ⇒ `target = 0`。
16944 的註解自己寫著：「校正量每輪重算又會讓車前後跳（使用者回報的『倒退跑』）」。

**漏洞**：`applyTrtcBoardBackend` **直接寫 `_easedShift` 的內部狀態**，繞過上面整道閘門：

```
index.html:17871  const ek = trtcEasedMotionKey(ln, tr, physicalKey), old = _easedShift.get(ek);
index.html:17872  if (old) { old.cur = visualShift; old.sim = motionSec; old.at = performance.now(); }
index.html:17873  else _easedShift.set(ek, { cur: visualShift, at: ..., sim: motionSec, ep: _metroGateEp.ep });
```

`easedShift()`（16774）讀到的就是這顆被外部塞進去的 `cur`；`target=0` 只讓它以
`fall = adv * (maxRate-1)`（約 0.33× 模擬時間）慢慢衰減，下一輪看板又整個重設回 `visualShift`。
消費端 `freqTrainBaseAt` 5273–5274 `shifted = rosterTime - sh` ⇒ 車被畫在班表位置的 sh 秒**之前**。

**實測（正式站，headless chromium，`?g=metro`，zoom 13）**

1. `metroLiveOn(ln) === false`，但同一次呼叫 `metroShiftSec(ln,tr)` 回 `15.99 / -21.98 / 83.99 / 55.99 …`，
   **恰等於 `ln._trtcBoard.shifts.get(tr)`**（16 / -22 / 84 / 56）。→ `docs/audit-20260817/audE.mjs`
2. 只讀 `draw()` 自己產出的 `state._freqHits`（不呼叫任何會推進狀態的函式），105 秒 / 87 台車：
   **99 次「牌在螢幕上往回退」，涉及 31 台車；單步最大回退 49.6 px**（zoom 13 ≈ 860 m）。
   回退時刻集中在 simSec 38083.93 / 38099.03 / 38128.98 / 38144.07 / 38163.2 —— 約 15 秒一次，
   ＝看板輪詢節奏；**一次事件同時打到 26–33 台車**。→ `audF.mjs`

**畫面上長什麼樣**：捷運頁靜靜看著，每十幾秒整條線的車號牌會**一起抽動一下**——大多數往回退幾像素到
幾十像素，少數往前衝（實測最大單步 50 px 後退、36 px 前衝）。同一瞬間方向箭頭仍指著行進方向，
所以看起來就是「車倒著走」。這不是官方資料在跳：正式站此刻的官方名冊是 `outage`、`vehicles: 0`。

## F2（P1）捷運命中框沒吃牌寬 → 點在這顆牌上，跟隨的是旁邊那台車

`freqTrainsAt`（9700）的 `contains`：

```
index.html:9704  return h.halfW != null ? Math.abs(dx) <= h.halfW && Math.abs(dy) <= (h.halfH || 8) : d < 18;
index.html:9709  if (!OFFICIAL_ROSTER_ENABLED || !officialHere) { …最近一顆… }
```

`halfW` **只有官方名冊路徑會塞**（6101–6107）。純班表與班距幽靈車 push 的是
`{ x, y, ln, tr }`（6193）／`{ x, y, ln, k }`（6209）——沒有 `halfW`
⇒ 一律退回「18px 圓內取離中心最近的一顆」。而牌是 **22×15 / 17×15 的矩形**
（`drawTag` 6864：`pw = measureText+10, ph = 15`）。
圓 18 > 牌半高 7.5，也 > 牌半寬 8.5–12 ⇒ **點在牌的左右邊緣時，鄰車的中心常比自己的中心更近**。

**實測**：zoom 13、畫面上 78 顆北捷牌逐 2px 掃描自己的牌面矩形：
- **27 顆（35%）的牌面有 >25% 的面積會選到另一台車**（最高 53%）；
- 1 顆整顆牌**沒有任何一點點得到自己**。→ `audI.mjs`

**真滑鼠端到端**（`audK.mjs`）：紅線某牌盒 x∈[609,625]，在 **x=613（牌面之內）** 按下去，
跟隨卡打開的是 **「台北捷運 中和新蘆線（迴龍）· 往 迴龍」**——完全另一條線的車，
而且沒有跳任何歧義選單。

**畫面上長什麼樣**：點紅線的「R」牌，右下角卻彈出橘線往迴龍的跟隨卡；地圖鏡頭飛到別台車身上。
對向同色車互搶更常見（BR↔BR、R↔R 實測 wrongPct 32–53%）。

## F3（P1）疊車選單在正式站結構上打不開，被蓋住的那台永遠點不到

`freqTrainsAt` 9709 的 legacy 分支 `return best ? [{ … }] : []`，**回傳長度上限＝1**。
`map.on('click')` 21844 的 `if (fhs.length > 1)` 因此在 `OFFICIAL_ROSTER_ENABLED=false` 時**恆為 false**。

**實測**：zoom 13 畫面上有 **21 對牌互相重疊**（中心距 < 兩半寬和且 y 差 <15px），
包含兩顆 `R` 只差 **1.0 px**、`R` 與 `O_XINZHUANG` 差 3.2 px。
對每一對的 A 中心、B 中心、兩者中點各探一次，`freqTrainsAt` **全部回傳 1 筆**。→ `audG.mjs`
（對照組：把兩台**官方**車放進 `_freqHits` 並點在框內，同一支函式回傳 2 筆、選單會開 → `audM.mjs`）

**畫面上長什麼樣**：兩台同線車交會時畫面上只看得到一顆「R」牌（同字同色完全重疊），
使用者不知道那裡有兩台；怎麼點都只會跟到其中一台，另一台在牌分開之前完全點不到，
而 memory 記的「重疊車點不到已解＝命中框吃實際牌寬＋疊車選單」在正式站是關著的。

## F4（P1，目前潛伏）官方車命中框外 9–18px → 車的身分被丟掉，跟隨卡停在終點站不動

同樣是 9709 的 legacy 分支：它回傳 `{ ln, k, tr, dist }`，**沒有 `vehicleId`**。
官方車的 hit 本來就沒有 `k` 也沒有 `tr`（6106–6107 只塞 `ln / vehicleId / officialNo`），
所以框外 12px（仍在 18px 圓內）的點擊會拿到 `{ ln, k: undefined, tr: undefined }`。

**實測（用 6106 真正 push 的形狀，同步呼叫真的 `freqTrainsAt`，`audM.mjs`）**
- 框內 (0,0)：回 `vehicleId:"V-TEST-1"`，`trtcOfficialSameTarget` → **true**（再點一次可取消跟隨）
- 框外 (0,+12)：回 `vehicleId:"undefined"`，`trtcOfficialSameTarget` → **false**
- 兩台官方車重疊：框內回 2 筆（選單會開）、框外回 **1 筆且無身分**

把這個形狀餵進真正的 `applyFreqFollow`（6294，`audL.mjs`/`audM.mjs`）：
`trtcOfficialHitFromTimetable` 因為 `!hit.tr` 直接原樣放行（6288）→
`state.freqFollow = { ln, k: undefined }`（6306）→ `updateFreqFollowCamera` 6368
的 `f.k >= ln.n` 對 `undefined` 為 false、擋不住 → `freqTrainInfo(ln, NaN)`。
結果：`applyFreqFollow` 回 **true**、跟隨卡打開寫「台北捷運 文湖線 / 動物園」，
鏡頭飛到 **[24.9983, 121.5795]（動物園）**，**6 秒後位移 0 m**，`state.freqFollow` 仍在。

**畫面上長什麼樣**：點官方車牌上方／下方一點點（沒中框），畫面不是「沒反應」，而是
鏡頭一口氣飛到那條線的終點站、跟隨卡出現卻永遠停著不動；再點原來那台車也取消不掉
（`sameTargetOutside=false` ⇒ 會再開一張新的幽靈跟隨）。

> 目前潛伏：需要 `?officialroster=1` 且上游名冊活著才會走到。今天實測 `feedMode="outage"`。

## 查過、確認沒問題的（別再追）

- **牌與圓點不同源？** 沒有。`drawTag` / `drawDot` 吃的都是同一個 `cp`
  （純班表 6187、官方 6095），畫的都是真實位置，沒有任何避讓位移。
- **箭頭本身反了？** 沒有獨立的箭頭反向缺陷。105 秒 87 台車裡「箭頭與該步位移夾角 >90°」的 36 筆
  **全部落在 F1 的彈跳時刻**（38083.93 / 38099.03 / 38128.98 / 38144.07 / 38163.2）——
  箭頭一直忠實指著路線行進方向，是牌被 shift 拉回去。F1 修掉這條就一起消失。
- **官方路徑 `trtcOfficialPositionProgress`（5087）在 `atStation` 用 `findIndex(lat/lon 完全相等)` 取站序，
  重複座標會取錯站？** 實測九條北捷線**沒有任何一條**有重複的站座標（0 筆，`audJ.mjs`）⇒ 不成立。
- **跟隨會不會被看板輪詢洗掉？** 不會，真點擊後連跟 75 秒全程未中斷（`audK.mjs`）。
