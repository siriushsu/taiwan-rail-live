## 〇、三句話結論

1. **那 18 分鐘（1069/1611/1744 秒）不是誤點，是我們自己算錯。** 官方的車今天準點在跑，是後端的逐班綁定器把車釘在「早 k 個班距」的那一班上，於是 `shift ≈ k × 班距`。決定性證據是**成長率**：同一趟車的 shift 在 676 秒牆鐘內長了 1081 秒（1.60 倍）——誤點的成長率上限是 1 秒/秒，超過 1.0 在物理上就不可能是誤點。
2. **今天早上把北捷改成「純班表」的修法，沒有真的純。** `index.html:17871-17873` 在純班表模式下仍然無閘門地把校正量寫進 `_easedShift`，實測正式站 23/99 台在跑的車位置仍被拖動，最大偏離班表位置 **1685.8 公尺**。使用者回報的「倒退跑」因此沒有被修掉，而更新紀錄上那句「位置是依班表推算的」目前對約兩成的車是假的。
3. **一直出錯的結構性原因是：判準幾乎全部落在管線自己算出來的中間量上，而不是使用者看得到的畫面座標。** 這使得「實作錯了、判準跟著一起錯」變成常態——上一輪 40/40 契約、16/16 突變、17/17 前端全綠之後上線，使用者一眼看出壞掉；而今天實跑發現，**五支唯一會量畫面座標的 gate 全部在 import 期就死掉、輸出裡連一個 ✅ 都沒有**，跟「跑過而且全過」長得一模一樣。16 條使用者可見性質裡有 **9 條無人守**，正好涵蓋今天四次回報的全部內容。

## 一、那 18 分鐘的校正量是怎麼來的

### 1.1 結論

**是算錯不是誤點。** 校正量幾乎等於「我們配到的班次跟正確班次差了幾班」，不是「車晚了多久」。

### 1.2 可複現的算式（單一個案，完整到可以逐位重算）

中山國小 407 號車，2026-08-17 10:17 那一輪：

| 項目 | 值 | 出處 |
|---|---|---|
| 官方回報 | `{no:"407", line:O_XINZHUANG, dir:1, from:9, to:8, run:96, arrEpoch:1786933167}` | `/api/trtc-live` payload |
| 推得離站時刻 | 37167 − 96 = **37071（10:17:51）** | — |
| 被綁到的班次 | `20@33960>0@36817`，該班在站 9 的表定發車 = **35460（09:51:00）** | `scripts/trtc_board_ledger.mjs:1140`、`:995` |
| 產出的 shift | 37071 − 35460 = **1611 秒** | 同上 |
| 前端照抄 | `visualShift = 37167 − 35556 = 1611` | `index.html:17862` |
| **真正對得起來的班次** | `20@35580>0@38437`，站 9 表定 37080（10:18:00） | 原始班表 `data/trtc_times.json` |
| **真正的誤差** | 37071 − 37080 = **−9 秒（準點）** | — |

同一輪另一筆更乾淨：迴龍 terminal 列 `arrEpoch 1786933324`（10:22:04）被綁到 `tr[1]=35580`（09:53）→ shift 1744；正確班次是 `20@37320`（10:22:00）→ **+4 秒**。

這個等式在整份 payload 上普遍成立：10:17 輪 **89/89**、10:55 輪 **87/87** 逐筆重現（獨立重寫的腳本，不 import 任何產品模組）。

### 1.3 為什麼確定不是真誤點（四條互相獨立的證據）

| # | 證據 | 數字 |
|---|---|---|
| **E1 成長率超過物理上限** | 同一 trip key（`G_XBT dir2 key=0@35220>1@35423`）跨兩份快照追 shift：2393 → 3474，牆鐘只走 676 秒 ⇒ shift 長了 **1081 秒 = 1.60×**。誤點成長率上限是 1 秒/秒。1081 ≈ 該線班距 1080。反向也有：`BL dir1` 的 shift 從 581 掉到 43（−538 ≈ BL 班距 540）——誤點不會往回跳一個班距。 | 1.60× |
| **E2 誤差被量化成班距的整數倍** | `payloadShift − bestShift` 全部是班距整數倍（276/552 = BR、540/1080/1620 = 新莊線、480、1140…共 44 筆）。真實誤點不會量化。k = shift ÷ 局部班距 逼近整數：`R_XBT 5401/600 = 9.00`、`O_LUZHOU 1168/588 = 1.99`、`O_XINZHUANG 1734/576 = 3.01`。 | k 誤差 <0.01 |

| **E4 對整份班表掃「最佳可行差」** | 286 筆官方站間錨點，逐筆掃同線同終點的所有表定班次取最佳可行差：中位 **+24 秒**、p95 +114、**\|差\|>300 秒 = 0 筆**；41 筆起點列全部落在 −124～+137 秒。同一批錨點，我們實際綁到那班的差有 **111/286（39%）超過 300 秒**。 | 39% |

另有兩條輔助但不足以單獨定案的旁證：行程自洽（18 台車的起點 depEpoch 對上班表同段耗時，全落在 −4～−164 秒），以及起點看板實測 11:00:45 報發車、表定 11:00:00（晚 45 秒）——起點準點發車與線上車晚 29 分不可能同時為真。

### 1.4 錯誤為什麼會「永久自洽」——真正的根因

綁定器的決勝成本是 `cost = |shift − ref|`（`scripts/trtc_board_ledger.mjs:1143-1144`），而 **`ref` 是同 line|dir 20 分鐘窗內、綁定器自己當下那批綁定的 `lastShift` 中位數**（`:1004-1015`）。安全閥比的也是 `|lastShift − ref|`（`:1017-1023`）。

於是整群一起漂走時：

- 群體偏移量對 `cost` 沒有貢獻（大家都偏一樣多 ⇒ cost 恆小）；
- 安全閥的差值恆為 0 ⇒ **結構上永不觸發**（交錯年齡模型下十輪 `evictedSafety = 0`）；
- 收班判定 `nowSec >= tr[末] + lastShift + 120`（`:1180`）被 shift 自己撐開 ⇒ 錯的班次還被延長壽命。

**判準與實作同源，錯一次就自己維持自己。** 受控實驗（同一份 `/api/trtc-live` 快照 `at=1786935266`，只改「先前狀態」一個變因）：

| 條件 | `O_XINZHUANG dir1` 六台車的 shift |
|---|---|
| 沿用線上狀態，重放十輪 | `[1662, 1732, 1736, 1780, 1782, 1785]`，十輪不動 |
| 只清掉該方向的 prior（或整線冷啟動） | `[−18, −8, −4, 40, 42]` |

新生的車還會**繼承**偏移：正式站連續輪詢 3 分鐘期間新生一台（trip `38460@…`），**直接以 shift=1764 出生**，全程無人介入。

出口也被封死：把某一台的綁定拿掉重放，正確班次不是被 `capped` 擋，而是被鄰居 `occupied`、被禁早發 `tooEarly`（−90 秒）或被 `noReversal`（`:1142`）擋下。全網 84 筆逐一拿掉重放的阻擋原因分佈是 **occupied 343 / tooEarly 68 / noReversal 20 / capped 18**。

### 1.5 修法（比原提案保守，且有實測支撐）

原稽核提的「決勝準則改成最小 |shift|」**經實測是淨負的**：全網綁得回來 67→63、綁不回來 17→21、capped 18→28，車不是回到準點，是直接失去綁定。實際該做的是：

1. **群體同量偏移偵測 + 整群鬆綁**：偵測「整群 shift 同時 ≈ k × 班距」，一次讓那一群同時鬆綁（實驗 E 證明：同一份資料立刻收斂到準點 `[−18, −8, −4, 40, 42]`）。
2. cost 的錨點要換成**與實作不同源**的量（與班表的絕對距離、官方回報的實際班距），不能是 records 自己的 `lastShift`。
3. 必須補「shift ≥ −90」（87 台裡 bestShift < 0 有 18 台、< −90 有 5 台，直接放最小 |shift| 會允許早發）。
4. 必須加**遲滯項**：`|shift| ≈ 半班距` 的近平手若每輪重取最小，車號會在相鄰兩班之間翻面跳動——這正是 `trtc_board_ledger.mjs:1016-1017` 註解自己警告的、也是使用者 08-07 裁示「不要每次打開都重算一次」要防的。
5. 「unbound 就回純班表」在前端**不成立**：`index.html:17321` 是 `target = v != null ? v : ln._trtcBoard.all`，沒配到的車吃全線中位數。不改這一行，第 1 點是 no-op。

## 三、檢查方式為什麼會集體失明

## 四、「一直出錯」的結構性原因，與重做後的判準規格

### 4.1 那個機制（不是 bug 清單，是機制）

> **我們用「管線自己算出來的中間量」當真值去驗「管線」。**

這一句可以解釋今天全部六族缺陷：

| 顯形 | 同源在哪 |
|---|---|
| 綁定器把車釘在早 k 班 | `cost` 的錨 `ref` = 綁定器自己的 `lastShift` 中位數（`trtc_board_ledger.mjs:1004-1015`）；安全閥比的也是它 ⇒ 整群偏移時恆不觸發 |
| 收班判定失效 | `nowSec >= tr[末] + lastShift + 120`（`:1180`）用被污染的 shift 當門檻 |
| 「純班表」不純沒被發現 | 判準看 `metroLiveOn`／`anchored`（都正確回 false／0），沒有一條看「畫出來的點離班表位置幾公尺」 |
| harness 全綠 | 判準讀 `state.vehicles.from/to`，而失效發生在它下游的顯示狀態機 |
| 上一輪 40/40 契約全綠仍退貨 | 判準全部落在 `roster.positions`、`motionFrom/motionTo`、`timeline`、`coastCycle`、`shifts` |
| 疊車在 gate 下合法 | 判準對象是「整數站號的擁擠度」與「順序符號」，畫面上的公尺距離無人量 |

第二層機制：**否定式與同形失效沒有訊號**。ENOENT 死在 import 的腳本，輸出與「全部通過」完全同形；旗標翻面後 gate 的覆蓋對象靜默變成空集合，也沒有任何訊號。**沒有訊號的錯誤不會被修，只會累積。**

### 4.2 重做後的判準規格（已完成，七條 + 三總則）

完整規格在 `判準規格-北捷位置重做.md`（401 行），每條都附「使用者可見性質／量什麼／判準怎麼寫／為什麼不漂移／突變測試／正向對照」。

**三條總則（違反其一整份驗收作廢）**

1. **真值來源與被測物不得共用任何推導假設。** 只有四類東西可以當真值：已繪製輸出（`state._freqHits` 的 `x,y`，`index.html:6194`／`6110`）、上游原始輸入（`state.trtcOfficialBoard.rows[]`）、靜態路線資料（`ln.shape`／`ln.cum`／`ln.stations`）、外部物理常數。**明文禁用** `roster.positions`、`motionFrom/motionTo`、`vehicle.timeline`、`coastCycle`、`ln._trtcBoard.shifts`、`boardPos.held`。
2. **判準不得呼叫有狀態的函式取值。** `easedShift()` 每次呼叫都寫內部狀態，`metroShiftSec()` 是它唯一入口 ⇒ 判準每格呼叫一次就是在跟 render loop 搶同一份緩動狀態。實測（板南線，同支腳本只差呼叫次數）：每格呼叫 → 28 次倒退；純輸出側量法 → 23 次（多數在像素量化底線內）。
3. **門檻寫「是什麼／怎麼排」，非寫數字不可時數字要從當下量到的東西推導。** 可以：`> 一列車的實體長度`、`≥ 1.5 × 當下每像素公尺數`、`順序不得反轉`。不可以：`< 60m`、`≤ 140px`、`恰 8 顆`。**既有的 60m 門檻作廢**——真正的物理界線是列車長度（高運量 6 節約 145m、文湖線 4 節約 90m）。

**七條判準**

| 判準 | 守的使用者可見性質 | 判準本體 |
|---|---|---|
| **A 不倒退** | V3、V15 | 逐格里程差沿其**淨位移方向**恆 ≥ −(1.5 × 當下每像素公尺數)。唯一豁免＝長時間斷訊回歸，且必須同時看到回歸 toast |
| **B 不疊車不超車** | V1、V4 | (a) 任兩台同軌同向車的前後關係符號在觀測窗內不得變號；(b) 里程差恆 **> 一列車實體長度**（下界式，補上 M1 的死角） |
| **C 只在起終點生滅** | V9、V5 | 第一次出現須落在起點站一站範圍內、最後一次須落在終點站一站範圍內。左右設限（窗首已存在／窗尾仍存在）必須明講並單獨計數 |
| **D 倒數＝官方逐字** | V11 | (a) `data-trtc-eta` 必須逐字出現在 `trtcOfficialBoard.rows`，不得被任何 shift 改寫；(b) 顯示文字解析回秒數後與 `eta − 牆鐘` 差 < 一個顯示單位 |
| **E 箭頭＝實際位移** | V6 | 箭頭方向與同一格實際位移向量夾角 < 90°（90° 是契約規則 11 自己寫死的界線） |
| **F 斷訊看得到** | — | 資料齡由前端自己從官方列時間戳算（**不得讀 `boardPos.held`**），超門檻時四處都要有說明文字、恢復後四處都要消失；**新鮮度逐上游分開算**，只斷一邊不得指控另一邊 |
| **G 在軌道上** | V13 | 投影到 `ln.shape` 的殘差 ≤ 1.5 × 當下每像素公尺數 |

**判準 H（元判準）**：每支腳本第一行要有自檢閘——印出「我驗的是哪棵樹、依賴齊不齊、總共跑了幾條斷言」，**斷言數為 0 時以非零碼收場**。今天五支死在 import 的腳本，症狀與「全部通過」完全同形，這一條就是為了讓那件事不可能再發生。

規格另附：harness 鐵則（語料與依賴必須在 repo 內，不得依賴 `/tmp/*`、repo 外或 gitignored 路徑；兩側旗標都要跑）、狀態空間覆蓋維度、以及對這份判準本身的 meta-mutation 驗收。

規格設計過程中已用正式站受控實驗**推翻了兩個原本要沿用的量法**：呼叫 `metroShiftSec` 取驅動量會污染被測系統（總則 2）；只在同一 `ln.id` 內配對會整段漏掉共線段。
