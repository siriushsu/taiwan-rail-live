# 車庫列車外觀考據與精修原則

日期：2026-09-12。使用者明確要求：外觀盡量考據正確，需要更改或加細可用 Blender。此要求適用後續各系列，先處理首發四款，不一次重製 62 款。

## 必須遵守

1. 先固定車型、具體車號或代表子型、年代、塗裝版本，再動模型。不把不同車號、改造前後、不同客車的細節混成一車。
2. 實車辨識優先：車頭輪廓、長短鼻、駕駛室、車身比例、兩側門窗配置、燈具、車頂設備、輪軸／轉向架、塗裝分界，先於螺絲等微小裝飾。
3. 門窗數、左右不對稱、受電弓／排氣位置及輪軸數不可只套共用模板。資料不足標為待核對，不憑記憶補細節。
4. 維持現有微縮風格。Q 版可以適度壓縮尺寸，但不能以 Q 版為由任意改變關鍵構造；展示尺寸不宣稱為真車工程尺寸。若壓縮需要刪窗或改配置，明列簡化並優先尋找保留真實配置的做法。
5. 真實編組與三節場景縮編分開。需要縮編時標示「三節示意編組」，仍保留端車／中間車、駕駛室、設備位置與運轉邏輯；不能把頭車直接當所有中間車。
6. 參考以製造商、營運機關、博物館資料及有日期／車號的原始攝影為主。每項修正留來源與所支持部位；看過介紹文字不等於看過照片。照片只作考據，不擅自作貼圖或隨產品發布。
7. 外觀準確與權利判斷分開：不為抽象風險任意改色或造出不存在的車。新增官方徽章／品牌圖案需重新核對權利與呈現方式，不能把本次無 Logo 檢視當成對新增圖案的結論。

內部權利、命名與免費一景討論，記於本機主工作目錄的 `授權查證-車庫原則-20260912.md`（gitignore 排除）；該筆記不是完成授權或全面權利排除證明。

## 本輪實際盤點

- Blender 可執行檔：`/Applications/Blender.app/Contents/MacOS/Blender`。
- 原始資產位於主工作目錄 `prototypes/tiny-trains/blender/fleet-v1/`，包含六款 `.blend`、`build_models.py`、`build_breezy_blue.py`、`model_specs.py`、`references.json`、`BLUE-REVISION.md`。
- 製作 worktree 沒有這批原檔；匯出 JSON 中的來源路徑不代表 worktree 內已有檔案。後續精修先複製所需來源到獨立修訂目錄，保留原檔，避免污染其他任務。
- 原 README 明示工程尺寸為空、比例與窗數有簡化；舊驗證不能當作逐項實車外觀驗收。
- `model_specs.py` 的 DR1000／DR3100 共用六窗、兩門與車頂模板，DR1000 另調長度與雙駕駛室。這是需優先拆開查核的實作事實，尚不據此斷言每個部件都錯。
- DL38／DL39／DL45 共用 forest_loco，但 DL38 有專屬小燈分支；須對照 DL38 本車，不可只憑「林鐵紅白機車」的共通照片重做。
- 藍皮已有 2026-09-08 兩輪修訂，參考 R135 與 35SPK32717；先讀其紀錄，保留已確認短鼻、燈具及塗裝修正。客車九扇主要窗與通風器仍屬明列簡化。

## Blender 修改及驗收

- 每項建立「參考車／年代 → 來源照片或尺寸 → 現模差異 → 修改 → 驗證」紀錄。來源不足的項目留待核對，不先編造修正值。
- 在獨立修訂目錄保存原生物件、腳本、材質、`.blend`、匯出 metadata／網格及前後渲染；不要只改壓縮 bin，或以改源腳本代替更新實際載入資產。
- 沿用 +X 車前、+Y 左、+Z 上及輪底錨點；GLB 軸向另依既有匯入約定。由 `scripts/import_garage_blender.py --source ... --models ...` 精準匯入本輪車款，不重匯整批。
- 靜態驗正、後、左右、斜角與車頂；背面不缺面、透明窗不穿幫、細線不共面閃動。
- 實際放回場景驗轉彎、跟車、遮擋、輪軌貼合、連結器／車距與日夜材質；視覺修改使用 Chromium／WebKit。手機檢查 360／375／414／768 與觸控，保留真機效能待驗的實際狀態。
- 完成度分為「資料待補」「差異已確認」「模型已改」「已匯入場景」「瀏覽器已驗」，不可混用。此次僅完成原則、來源與初步實作盤點，尚未精修模型。
