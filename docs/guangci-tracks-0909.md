# 象山—廣慈／奉天宮雙軌修正

原雙軌快照僅涵蓋紅線 stationIndices 1–27（象山—淡水），近景卻隱藏整條原始紅線，導致 index 0 的廣慈延伸段消失。這次將兩方向範圍擴充為 0–27，並讓抽換邏輯保留未涵蓋的原線區間，避免未來新增端點再次消失。

來源：2026-09-09 讀取 OSM Overpass 的 `way[railway](25.030,121.568,25.040,121.587)`，原始 8 條選用 way 保存在 `scripts/fixtures/guangci-osm-0909.json`。既有象山 way 197881274／197881275 不變，以相同 OSM node ID 接續 806179562／806179561、453081585／453081584、1555091760／1555091759；665025772／665025773 尾軌供完整車身沿既有軌道延伸。沒有直線補洞、平移座標或更動班表。延伸段兩方向長度約 1467.45／1461.96 公尺，資源不重疊。

來源連接段仍含 `service=yard` 標籤，保留原標籤並以明確共用節點的路徑納入此次行車區間；不是泛用開放列車進入所有側線。站台停止中心、方向指派以及地下深度仍為顯示推估，非實測工程資料。層位保留來源 tunnel=yes／layer=-2，重建固定 DEM 剖面及上下層剖面。

可重現：`node scripts/extend_guangci_physical.mjs`（已納入時不重複追加），然後以 NETWORK／OUT 指定 metro 檔執行 `build_physical_display_profiles.mjs`，再執行 `build_rail_levels.mjs`。

驗收：`verify_guangci_tracks.mjs` 檢查 2 方向各 1101 個進度點、象山邊界连续性、地下高度、原始 XY、股道不重用；已加入出貨閘門。`verify_guangci_browser.mjs` 驗證 Chromium／WebKit 的兩方向六節車、起終點與中途位置、平地／地形、軌道 A/B 像素，以及不完整資料的 fallback 範圍。

實測結果：廣慈專項 Chromium／WebKit 30 項通過，軌道 A/B 像素差分別為 4770／21533。手機 360／375／414／768 的兩引擎觸控驗收通過；Chromium 414 首次 boot 超時，單獨重驗通過。上下層全網檢查 4237 ways、5686 共用節點、339 交叉均通過。

既有問題：以本次修正前主線 `3a3ed018` 的 runtime 與剖面資料做瀏覽器 A/B，台鐵當時 143 班僅 86 班走實體股道，其餘 57 班使用原線形；新舊版數量完全相同，因此既有 `verify_physical_tracks_browser.mjs` 的全車 95% 覆蓋率門檻未通過。未調降或改寫該正式門檻；另用暫存副本保留失敗紀錄並繼續跑其餘案例。紅線則由 32 班中 31 班有實體股道改善為 32／32。

其餘股道回歸 120 項通過（共 122 項，另 2 項為上述兩引擎既有覆蓋率失敗）。更新紀錄雙引擎四種觸控寬度通過，最近 8 條／完整 308 條；多語系 2003 個 key 通過。
