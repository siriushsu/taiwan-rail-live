# 隧道縱坡（v0910a）

隧道的顯示高程原本是「地表減固定深度」：`level-profiles.json` 給每條隧道 way 一個
恆為 −8m 的 `offsets`，畫面上的高度是即時 DEM 加這個位移，於是隧道逐點貼著山坡走。
北迴線新觀音隧道在畫面上爬升 538 公尺，文湖線辛亥—麟光段出現 206% 的顯示縱坡，
南迴線中央隧道 592 公尺。全網路 340 條連續隧道裡有 332 條的顯示縱坡超過 5%。

舊閘門照不到這一類缺陷：`verify_rail_levels.mjs` 驗的是 `offsets` 的相鄰差，
而隧道的 offset 恆為 −8，差分恆為 0，永遠是綠的。

## 改法

沿用林口台地走廊那一手（`lib/linkou_rail_grade.mjs`），推廣到全網路，
新增 `lib/tunnel_rail_grade.mjs`，在 `build_rail_levels.mjs` 的層位求解之後執行：

- 依共用節點與同系統把隧道 way 串成連續隧道，共 341 條、711 個 way
  （林口走廊那 60 個已有 `terrainValues`，不重複處理）。
- **洞口固定**：與非本段股道相接的節點，沿用該股道畫在畫面上的高度
  （對方有 `terrainValues` 取它，否則是原始 DEM 加層位 offset），所以洞口不會出現落差。
- **內部沿里程調和內插**：單一鏈時解就是兩端洞口之間的直線。
- 每 100 公尺補一個節點，否則縱坡上限與覆土上界在長 way 中段完全不生效，
  節點之間的內插曲線也會比兩端弦線陡得多。
- 約束：縱坡上限（台鐵／高鐵 2.5%、捷運 4%、阿里山林鐵 6%）、覆土上界（地表減 8m）、
  交會淨距沿用已求解的上下序當上下界。上下界先沿縱坡錐體放寬到可行，
  否則投影會在兩個互斥的約束之間永遠來回。
- 兩端洞口高差本身就超過縱坡上限的短隧道沒有自由度，退回兩端弦線並另計為 steep（66 條）。
- 結果寫進 `terrainValues`，`map3d.js` 在開地形時直接用它當絕對高程；關地形仍走原本的層位 offset。

公尺值仍是顯示估計，不是實測縱斷面或工程軌面標高，`railElevationM` 仍為 null。

## 效果

| | 改前 | 改後 |
|---|---|---|
| 落差 > 20m 的隧道 | 183 | 66 |
| 落差 > 50m 的隧道 | 93 | 9 |
| 顯示縱坡 > 5% | 332 | 56 |
| 顯示縱坡 > 10% | 249 | 16 |
| 最大落差 | 633.9 m | 117.6 m |
| 最大顯示縱坡 | 206.7% | 36.5% |

新觀音隧道 538→29 公尺，中央隧道 592→23，永春隧道 560→13，新永春隧道 531→8，
文湖線辛亥—麟光 56→9。剩下最大的 117.6 公尺是阿里山林鐵獨立山一帶的短隧道：
兩端洞口的 DEM 高差本身就有 118 公尺，那是整條林鐵貼地顯示的既有性質，不是隧道特有。

## 驗證

`node scripts/verify_rail_tunnel_grade.mjs` — 驗**實際顯示高程**，不是 offsets。
核心判準是「隧道內部逐點都不得高過自己的洞口超過 8 公尺」（目前最差 5.8 公尺），
另驗洞口與相鄰股道接得上（1.5 公尺內）、共用節點連續（1 公分內）、
100 公尺視窗縱坡不超過系統上限，並有四條具名回歸各附舊剖面對照組。已掛進 `ship_web` 出貨前閘門。

突變測試四發，各自指名考哪一條，控制組還原後全綠：

| 突變 | 考的判準 | 結果 |
|---|---|---|
| 新觀音隧道還原成貼地剖面 | 內部高過洞口／顯示縱坡 | 紅：內部高過洞口 504.7m、縱坡 125.6% |
| 一條隧道整體抬高 3 公尺 | 洞口落差 | 紅：洞口落差 −3.00m |
| 中段 way 一端移動 2 公尺 | 接頭不連續 | 紅：接頭不連續 |
| 中央隧道中段插入陡坡 | 100 公尺視窗縱坡 | 紅：縱坡 54.7% > 3.5% |

`node scripts/verify_tunnel_grade_browser.mjs` — Chromium 與 WebKit 各驗三處，
比對畫面上取到的顯示高程與產物一致（誤差 < 3 公尺）且遠比其上方地形平緩，6/6 通過：
新觀音隧道畫面落差 28.7 公尺對地形起伏 185.4，中央隧道 23.1 對 298.9，
文湖線辛亥—麟光 2.3 對 11.3。

`verify_linkou_structures.mjs` 改用 `terrainBasis` 認林口那 60 條，
因為 `terrainValues` 現在全網路的隧道都有；該檔仍 60 ways／62 接頭／四處交會淨距 ≥ 7 公尺通過。

## 已知限制

- 洞口高程來自原始 DEM，山坡上的路塹、路堤與棧橋會讓它偏離真實軌面。
  阿里山林鐵受影響最大，因為整條線的地面顯示本來就跟著陡坡走。
- 求解器有兩條隧道未完全收斂（殘差 2.5 公尺以內），是覆土上界與交會下界互斥造成的極限環，
  顯示上看不出來；`build_rail_levels.mjs` 會印 `tunnelSolver` 供追蹤。
