## 1. 官方欄位說明（照抄字面，不自行推測）

### 1.1 臺北市 `GetEstimateTime` — 來源文件

《臺北市 Data.Taipei 平台 API 說明文件》**version 6.3**（2025-09-15），
下載自 `https://www-ws.gov.taipei/Download.ashx?u=…5daa0a37-8de7-4455-856b-de14a3b8a327.pdf`
（PDF 17 頁，628,974 bytes）。第 4 頁 `EstimateTime 預估到站時間` 表格逐字：

```
EstimateTime      預估到站時間
    屬性               Type                          說 明
RouteID           Number      路線代碼 (主路線 ID)
StopID            Number      站牌代碼
                     String   預估到站剩餘時間（單位：秒）
                              -1：尚未發車
EstimateTime                  -2：交管不停靠
                              -3：末班車已過
                              -4：今日未營運
GoBack               String   去返程 （0：去程 1：返程 2：尚未發車 3：末班已駛離）
```

第 9 頁 `Stop 站牌` 表格逐字（本批用到的欄位）：

```
Id                  Number   站牌代碼
routeId             Number   所屬路線代碼 (主路線 ID)
nameZh              String   中文名稱
nameEn              String   英文名稱
seqNo               Number   於路線上的順序
pgp                 String   上下車站別 （-1：可下車、0：可上下車、1：可上車）
goBack              String   去返程 （0：去程 / 1：返程 / 2：未知）
longitude           String   經度
latitude            String   緯度
```

實測值域（2026-09-11 10:07 那一份快照，29,358 筆）完全落在官方列舉內，沒有第五種負值：

| 欄位 | 實測分布 |
|---|---|
| `EstimateTime` < 0 | `-1`:4971、`-2`:155、`-3`:1887、`-4`:1243（其餘 21,102 筆 ≥ 0，範圍 0–9389 秒） |
| `GoBack` | `0`:10577、`1`:7437、`2`:9457、`3`:1887 |

🔴 **`-3` 的筆數 1887 與 `GoBack=3` 的筆數 1887 完全相同**，正好對上官方的
「-3：末班車已過」與「3：末班已駛離」——兩個欄位互相印證，不是我推測出來的。

### 1.2 與 TDX `StopStatus` 的對應

`scripts/bus_transfer_core.mjs:140` 既有註解已寫下 TDX 的官方值域
（`0 正常、1 尚未發車、2 交管不停靠、3 末班車已過、4 今日未營運`）。
兩份官方文件的**中文用字逐字相同**，因此臺北市負值 `-n` 對應 TDX `StopStatus = n`
是**照抄兩份官方文字後的對齊，不是自行推測**：

| 臺北市 `EstimateTime` | 官方字面 | TDX `StopStatus` | 官方字面 | 內部 `sourceState` |
|---|---|---|---|---|
| `-1` | 尚未發車 | `1` | 尚未發車 | `not_departed` |
| `-2` | 交管不停靠 | `2` | 交管不停靠 | `skipped` |
| `-3` | 末班車已過 | `3` | 末班車已過 | `last_bus_passed` |
| `-4` | 今日未營運 | `4` | 今日未營運 | `not_operating` |

`sourceState` 沿用 `bus_transfer_core.mjs:161` 既有的同一組字串，不另立平行詞彙。

🔴 **未見於官方文件、因此不解讀的東西**：`GoBack` 的 `2`／`3` 官方只寫「尚未發車」「末班已駛離」
而不是方向，所以 `GoBack ∈ {2,3}` 時**方向視為未知**（`direction: null`），不猜去程或返程。

## 2. 臺北市識別碼 ↔ TDX 識別碼 對照（2026-09-11 實測）

臺北市 blob 用數字 `Id`／`routeId`，TDX 用 `StopUID`／`RouteUID`。
實測發現 **TDX 臺北市的 `StopID`／`RouteID` 欄位就是臺北市 blob 的數字 id**
（`StopUID = "TPE" + StopID`）。分母分子：

| 方向 | 分子 / 分母 | 比例 |
|---|---|---|
| TDX 臺北市站牌列 → blob `Id` | 28,858 / 28,858 | **100.00%** |
| TDX 臺北市 `RouteID` → blob 路線 `Id` | 416 / 416 | **100.00%** |
| blob 站牌列 → TDX `StopID` | 28,858 / 28,861 | **99.99%** |

🔴 「數字相等」與被驗的實作同源，本身是零資訊，所以**另外用兩個獨立維度複驗**：

| 獨立維度 | 結果 |
|---|---|
| 配對後站名（正規化臺→台、去空白）相同 | **28,858 / 28,858 = 100.00%** |
| 配對後座標距離 ≤ 150 m | **28,858 / 28,858 = 100.00%** |

⇒ 不是 id 空間巧合碰撞，是同一批實體站牌。

**對不起來的 3 筆不靜默丟掉**，逐筆列出（全部屬 blob `routeId` 15724）：
`184110 頂坪`、`186832 橫嶺古道`、`211167 第二接續井`。

⇒ `GoBack = 2` 是全體最大宗（38.6%）。若當成方向硬塞，會有將近四成的列方向是瞎掰的。

兩列轉換前後（`normalizeDirectBulkRow` + `directBulkDirection`，碼表取自設定檔）：

```
原始  {"RouteID":10442,"StopID":36407,"EstimateTime":"62","GoBack":"1"}
轉換  {"state":"arriving","sourceState":"arriving","etaSec":58,"estimateSecAtSource":62,
```

## 4. 雙層 TTL 的算式（與實測節拍）

| 路徑 | edge `s-maxage` | isolate mem TTL | 實際上游間隔 |
|---|---|---|---|
| direct-bulk | 10 秒 | 15 秒 | 最小的、大於 15 的 10 倍數 = **20 秒** |
| tdx-per-stop | 30 秒 | 40 秒 | 最小的、大於 40 的 30 倍數 = **60 秒** |

🔴 **更正一項先前的量測**：先前用「每 20 秒探一次」量臺北 blob 的 `Last-Modified`，
得到「每 20–21 秒前進一次」並據此寫進註解說「20 秒＝來源自己的節拍」。
改用**每 10 秒探一次、連八發**重量（2026-09-11 10:55:11 → 10:56:21）：

```
Last-Modified 每一發都換新，相鄰間隔：10, 10, 10, 10, 10, 10, 10 秒
```

⇒ 來源節拍是 **10 秒**，先前那個 20 秒是**取樣間隔造成的疊頻假象**。
量週期的取樣間隔必須小於週期本身，否則量到的是自己的取樣間隔。
`worker.js` 的註解已改寫成這份量測。TTL 數字維持不變（20 秒＝每兩代取一代），
理由寫在註解裡：`etaSec` 會扣掉快照年齡，畫面倒數仍以「此刻」為準；
要追到 10 秒得每 10 秒重解一次 1.88 MB gzip，與「最多新 10 秒」不成比例。

守門人：`scripts/verify_bus_stop_frontend.mjs` 的「本批用到的 i18n 鍵沒有被後載入的字典遮蔽」。
本批自己宣告的鍵一個都不准被蓋掉；沿用的鍵則驗「最後生效值存在且語意分得開」。
正向對照用**既有的** `尚未發車[ja]` 遮蔽（`content-translations` 的「発車前」被
`bus-transfer-translations` 的「未発車」蓋掉）證明偵測器不是恆真。

**順帶記下、本批沒有動的既有重複鍵**（都不是本批造成，修它會改到別人的功能）：

| 鍵 | 兩處宣告 | 現況 |
|---|---|---|
| `尚未發車` [ja] | `content-translations`（列車語境「発車前」） vs `bus-transfer`（「未発車」） | 列車語境吃到公車的用詞 |
| `即將進站` [en] | `translations.js`（Arriving） vs `bus-transfer`（Arriving soon） | 生效 Arriving soon |
| `{n} 分` | `translations.js`（有單複數形） vs `bus-transfer`（純字串） | 生效純字串，單複數形失效 |
