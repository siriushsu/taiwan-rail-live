# 台鐵股道與行車曲線綁定修正

## 原因與範圍

`dispatch.json` 的停站簽章包含全部通過站到離時間。前端 `attachRunProfiles` 依最新行車曲線回填 `stop === false` 的推估通過秒數，造成 214 班的完整簽章不同；其正式停靠時間與站序都沒有改變，原派軌也沒有待避。因為 `motion.record()` 只接受完整字串一致，這些列車整班退回示意線形。另外 6841／6882 加開車沒有快照中的車次 key。

先前「08:00 的 143 班有 57 班未套用」包含 8888／8889 兩班程式合成的環島示意車。實際班表統計以 `!tr.loop` 判定，2026-09-09 共 907 班；修正後 691 班完整簽章、214 班推估通過時間更新、2 班已知路徑模板，全部有實體股道。當時活躍實際班次為 141 班、141 班有實體股道。

## 處理

- 正式停靠、起終點、站序仍精確核對。只放行明確不停靠、原快照也是到離同時、中途通過時間改變的案例；有待避／誤點安排或時間倒退時拒絕沿用。
- 新車次在同系統既有計畫中找完整有序站序切片，優先停靠型態一致與較短來源區間，再以固定來源 key 排序。沿用連通來源路徑，沒有直線補洞、橫移列車或根據鄰車臨時換軌。
- 加開車只借線形，待避全部為 0，採自己班表與行車曲線，不繼承來源班次的長度、延誤或接車安排。此為股道顯示推估，不是新的全網無衝突調度結果。
- 綁定結果由每班車的 WeakMap 保留，模板表延後到第一班缺 key 的加開車才建立；不在每幀重掃全部派軌。
- 沒有更動任何台鐵站點座標、時刻表、實體股道幾何或標高檔案。

## 驗證

`verify_tra_plan_binding.mjs`：完整班表、推估通過時間、正式停靠／站序／舊待避／時間倒退防護、30 班模板、反方向、未知站與跨系統／合成環島排除。`verify_tra_binding_continuity.mjs`：使用 1008／1007 及 6841／6882 的真實前端曲線快照，345 個取樣涵蓋兩方向，站點前後各 1ms 的最遠距離 0.0415 公尺，平地與地形高度均有限。以上兩項加入出貨閘門。

既有股道瀏覽器驗收使用原門檻 122／122 通過。快取回歸只對修改前已接受的班次逐值比對，新增覆蓋案例由上述綁定與連續性測試驗證。

雙引擎模型及高度驗收 64／64 通過：1008／1007、EMU3000 408（十二節標準編組）與 6841／6882，涵蓋出發、通過、抵達，平地與地形模式。未確認當班編組的車次依既有規則顯示三節示意，驗收不將它當成實際車廂數。

快取回歸：3612 個逐值取樣一致、545 次活躍路徑保留、34112 個定位案例、兩方向。更新紀錄 Chromium／WebKit 的 360／375／414／768px 觸控驗收通過，完整歷史 309 條；多語系 2004 個 key 通過。
