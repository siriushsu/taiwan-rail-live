# 台鐵抵站窗近失修正（輕軌看板出貨阻擋）

## 起因與界線

高雄輕軌看板修正 `9b7978a5` 出貨時，既有台鐵待避閘門失敗。相同原始輸入在看板修改前 `d09307a8` 也失敗，因此不是輕軌看板造成的回歸。使用者同意處理後，另以 v0928b 修正；不改高雄輕軌的 GPS、認車、位置或 Core 開關。

09/28 固定案例：145 次汐止官方到站 17:47、離站 17:48；5241 次的通過估計卻是 17:46:58。原推論因 5241 的長跑段包含新馬／和仁速限區，略過整條跑段的停靠窗約束。後續替 145 在百福新增待避，原始運動曲線在 17:43:43、17:46:18、17:46:58 三次交換前後次序，其中兩次不在停站中。

這個數字來自 `trainSeg` 的原始運動曲線，不是最終防追撞後的畫面碰撞數，也不是實際營運測量。

## 修法

- 保持官方停靠時刻、車種極速及防追撞 120 秒上限不動。
- 僅對原本略過的彎道長跑段，補上同向車「即將抵達既有官方停靠窗」的近失校正。須同日開行、方向相同、共同上一官方停靠站仍在後方。
- 近失範圍沿用該停靠窗的既有安全裕度 `min(30, floor(dwell / 3))`，不是全面解所有站間追越。互不相容的停靠窗整顆拒絕。
- 重建時保護速限區節點及先前已接受的抵站錨點；建不出合格曲線就保留原值。其他彎道交會規則仍未開放。
- 新規則統計另列，既有 MR1 分母和門檻完全不變。離線預算與瀏覽器共用同一套程式。

曾試過不限近失範圍，但 09/13 的 223／277 頭城推論會新增頂埔待避，連帶使 223／4193 在羅東發生新的畫面重疊，全日 A 類由 7 增至 9；該版本已棄用。較大時序衝突仍需要另案處理，不宣稱已修好。

## 驗證

- 新增 `verify_tra_zone_arrival.mjs`，掛入正式出貨鏈。固定 `9b7978a5` 的原始班表、通過觀測與幾何，停用預算表以驗現算模型，不隨每週班表滾動換題。
- 80 項雙向合成斷言：近失邊界、原本在前方、無共同上一停靠站、不同開行日、反向、已在停靠窗內、遠距離抵站、互斥停靠窗、官方端點、彎道速限及前次錨點保護。
- Chromium／WebKit：145 的官方 17:47–17:48 不變；5241 改為 17:47:20 通過；不再加百福待避；前後次序僅在汐止停站中交換一次；兩處速限區保留，頁面例外 0。
- `TRA_ZONE_MUTATION=skip` 還原「有彎道就整段跳過」後，固定案例立即失敗，重現百福假待避與三次前後次序交換。
- 原有雙向待避閘門通過：235／5245（牡丹）、114／228（五堵）；清站間隔皆 30 秒、倒退 0，煞車提前量分別 84.2／126 秒。
- 固定 09/13 全日實體股道驗收：570 個時點，19 PASS／0 FAIL；A=7、A′=9、B=37、C=13，逐項等於既有基線，沒有改門檻。這仍代表存在既有殘餘，不是零互穿。
- `build_run_profiles --check`：MR1 244／17，與既有基線相同；預算表 343 個車次號。當前多日聯集的新規則套用 8 處、拒絕 0 處。
- Chromium／WebKit 離線／現算對照：各 55,333 個執行期欄位、33,752 個停站節點、20,042 條曲線皆 0 差異，stale=0。

出貨仍須全套 `ship-web` 閘門與正式站收貨。輕軌看板本身的驗收見 `klrt-board-directions-20260928.md`；以上不構成輕軌定位精度或私有 Core 通過驗收的證據。

## 出貨環境的第二個阻擋

完整出貨跑到觀看控制驗收時，Chromium 的 1180×820 觸控平板情境回報 `mobile=false`、`side=false`，6 項失敗；相同腳本在未含台鐵修正的 `9b7978a5` 完整重現，WebKit 正常。兩次均未到 upload／deploy。

獨立空白頁設定 `isMobile:true, hasTouch:true`，Chromium 149／Chrome 153 仍可能回報 `maxTouchPoints=0`、`pointer:coarse=false`、`any-pointer:coarse=false`；另一次 Chromium 成功，顯示不是穩定的產品斷點問題。呼叫原生 `Emulation.setTouchEmulationEnabled({enabled:true,maxTouchPoints:1})` 後回到 1／true／true；無觸控對照維持 0／false／false。

因此只在 `verify_view_btn_side_entry.mjs` 的 Chromium 測試頁、載入產品前明確設定原生觸控，並新增「粗指標及觸控點已生效」斷言。沒有覆寫 `matchMedia`、DOM class、CSS、產品程式、既有幾何或點擊判準；WebKit 不改。

修正後重新執行完整 `verify_view_controls_gate.mjs`：exit 0，原有沉浸模式、車身比例、地形與側欄按鈕驗收全過，新增的 6 個觸控前置檢查也通過。網站程式和 BUILD 保持 v0928b，不因測試修正另改產品。
