## 1. 現況量測（正式站，2026-08-14 早尖峰，30 輪 × 5 秒）

探針在 `scripts/probes/`，三支都是唯讀、直接對 `https://railisland.tw/api/trtc-live` 拉，
不需要金鑰也不寫任何東西回去（產物落在 `./tmp/`）：

| 探針 | 量什麼 |
|---|---|
| `node scripts/probes/probe_roster.mjs <輪數> <間隔ms>` | 每輪車數、資料齡、gone／born／moved／reanchored／past |
| `node scripts/probes/probe_jump.mjs <輪數> <間隔ms>` | 同一台車同一區間，位置在同一瞬間位移了多少 |
| `node scripts/probes/probe_churn.mjs <輪數> <間隔ms>` | 消失的車是「真的不見」還是「換號」（見第 3 節） |

**要在營運尖峰跑才有訊號**（離峰車少、feed 也穩，量不到問題）。

量到的四個症狀與機制：

| 症狀 | 機制 | 數字 |
|---|---|---|
| 到站後不動 | `now >= arrEpoch` 直接凍在 `to` 站 | 每輪平均 **70.9／186 台（37%）** 已越過自己的 arrEpoch |
| 整批消失 | `now - sourceRevision > 30` 讓整份名冊失效 | 資料齡 max **32.9 秒**，30 輪中 **2 輪**超標 ⇒ 那兩輪全線的車同時不見 |
| 不斷跳動 | 官方每輪重給 ETA，同區間位置瞬間位移 | **494 次**；中位 8%、p90 **34.1%**、p99 87.7%、max **100%** 的站間距；其中 **212 次往後退**；3 次非相鄰跳站 |
| 中間消失 | **前端讀不到就整包清空**（見下）＋後端名冊配不到就刪車 | 30 輪內 73 台消失／80 台新生；40 輪版：248 台消失＝到終點站 11 ＋ 換號 18 ＋ **「真的不見」219** |

**「真的不見」那 219 台的真相**（`probe_group.mjs 14 8000 BL 1` 拍到的）：
BL 往西 15 台車，第 9 輪與第 12 輪 **`rev: null`、`n: 0`、整包讀不到**，下一輪 15 台原封不動
全部回來。也就是 **14 次輪詢有 2 次讀不到（約 14%）**，而舊碼一遇到讀不到就
`trtcOfficialRosterOutage('fetch-error')` ⇒ 整條線的車同時消失、連跟車都被
`clearFreqFollow()` 清掉。使用者說的「資料讀取的時候車子會一直被判斷不在那邊」講的就是這件事。

🔴 **本檔 09:20 版曾寫「若一律續推 600 秒會有 411 台幽靈，全隊只有 170 台，不准做後端續推」——那個數字是錯的，已作廢。**
它是拿「探針自己整包讀不到」當成「後端刪車」算出來的：讀不到的那一輪全線 170 台會一次
全部被記成消失。使用者當場指出「每輛車我們都編號了，哪裡生出來的幽靈」，是對的。

**幽靈只有兩個來源，而且都是逐台可檢查的條件，不是否決續推的理由：**

1. **同一台車這一輪被重新發號**（舊 ID 死、新 ID 生）。續推舊 ID ⇒ 畫面上兩個標記代表同一台車。
   已知兩個成因：(a) 官方改標終點站 ⇒ `groupKey = line|dir|dest` 換群組，
   `alignOrdered()` 配不到；(b) 官方 ETA 把車往回修一站，撞到 `matchFeasible()`
   「只能沿站序前進」的硬約束（trtc_official_roster.mjs:119）。
2. **車真的跑完了**（`to === dest`，到終點站離開營運）。留著就是一台停在終點站不走的假車。

payload 實況（做設計前先確認過的）：`boardPos.vehicles[]` 帶 `history`（186 台中 138 台
有 ≥2 筆）、`dest`、`dir`、`run`（中位 95 秒、p90 172 秒）、`tripKey`。
**注意 `run` 可能比 history 相鄰兩筆的間隔還大**（實測有 `run=109` vs `span=90`）。

### 3-2 前端：位置平滑層（「不斷跳動」）

現在 `trtcOfficialVehiclePosition` 是純函式，官方一改 ETA 位置就瞬移（494 次、212 次往後退）。
使用者要的是「不要一直跳」，不是「更準」。

設計（已想過但**還沒寫任何一行**）：

- 讓位置函式每個分支都回一個**沿路線單調遞增的純量** `prog`：
  `step = dir===2 ? 1 : -1`；站上＝`step*站序`，區間內＝`step*from + fraction`。
  已驗證這個量對固定的一筆 vehicle 記錄在 `now` 上是連續且單調遞增的（續推段也是）。
- 另開 `trtcOfficialDisplayPosition(ln, vehicle, now)` 當**唯一的顯示入口**，
  內含一個 `Map` 記 `${lineId}|${vehicleId} -> { prog, now }`：
  - 往後退 ⇒ **凍住不倒退**（＝台鐵 easedShift 那層的既有做法：誤點上升就凍結）；
  - 往前跳 ⇒ 限速追上，最多 `(1+3)/run` 段/秒（約 4 倍自然速度，34% 的落差約 8 秒補完）；
  - `now` 與上次差太多（切分頁、休眠）就直接重新對齊，不要慢慢爬。
  - 時鐘不在「現在」（時光機）時**不套平滑**，直接回純值。
- **`trtcOfficialRenderItems`（index.html:4578）與 `trtcOfficialVehicleInfo`（index.html:4568）
  必須走同一個入口**，否則畫面用平滑值、跟隨相機用原值，跟車會偏心。
  命中測試走 render items，自動一致。
- 純函式 `trtcOfficialVehiclePosition` 保持不變 ⇒ 現有 B／G 閘門與「arrEpoch bit-exact 到站」
  全部不受影響。

驗收要加的斷言：連續 `now` 序列中 `prog` 單調不遞減；注入一筆「往後退 34% 的 ETA 修訂」後
畫面位置不倒退且在 N 秒內收斂到新值；往前跳 100% 時每秒位移有上界。
突變：把凍結拿掉、把限速拿掉、把時光機豁免拿掉，各要轉紅。

## 4. 規矩（別踩）

- **驗收器的 VM bundle 是白名單**：`buildProductApi()`（verify_official_roster_frontend.mjs:125）
  與 `followRuntime()`（同檔 ~341）用 `extractConst`／`extractFunction` 把具名符號抽進 `vm`。
  新增任何 module-level const 或 helper，只要被抽進去的函式引用到，**就要同步加進 bundle**，
  否則整支腳本 ReferenceError 中止——而那個中止**不算轉紅**，會讓人以為驗過了。
- 錨點註解每個只准出現一次（腳本開頭有 gate）：`ROSTER_FRONTEND_ACTIVE`／`_POSITION`／
  `_RENDER`／`_GLYPH`／`_TARGET`／`_GEOMETRY`／`OFFICIAL_PAYLOAD_SCALAR_GUARD`／
  `OFFICIAL_PAYLOAD_TIMING_GUARD`／`OFFICIAL_POSITION_AXIS_GUARD`／
  `ROSTER_FRONTEND_REVISION_HIGH_WATER`。
- M-B 的突變字串是 `'if (now >= arrEpoch) return'`，M-A2 是
  `'now - revision <= TRTC_OFFICIAL_ROSTER_MAX_AGE_SEC'`——改到那兩行時要保留字面。
- 判準不要綁在會漂的量上，也不要與實作同源（本輪 G 閘門就是照這個寫的）。
- **更新紀錄**：首層 `data-cl-of` 上限 8 條、正本 `data-cl`，由
  `verify_plus_subscription.mjs` 的 CL0/CL1/CL1b/CL2 把關；只寫「真的到過使用者手上」的缺陷。
- **部署**：這是功能批次，**必須先上預覽站給使用者親試、拿到明確 go 才升正式站**。
  wrangler 一律 `arch -arm64 node ./node_modules/wrangler/bin/wrangler.js`，
  從乾淨 detached worktree 出貨（`.gitignore` 對 wrangler 無效，只有 `.assetsignore` 有效）。
  驗線上內容要帶 `-H 'Cache-Control: no-cache'`（`?cb=` 對 static assets 無效）。
- App 端：`~/Desktop/軌島_1.4.3_build49.ipa` 已建置驗畢待使用者上傳，**48 作廢**。
  這批修好之後要重出 build 才會進 App。
