# 北捷官方列車生命週期（唯一有效契約）

> 2026-08-14 定案。這份文件取代 2026-08-13 的官方名冊／到站稽核與未驗證續推草稿；
> 被取代文件已移除，不得從 git 歷史把其中的時間刪車、班表主體或重新配對規則搬回來。

## 產品規則

1. 起點倒數第一次出現時建立一台車並分配 `vehicleId`。冷啟動若剛好在營運途中，允許用
   當下官方列建立一次初始名冊；每台車都必須保存可稽核的官方站牌出生證據。初始名冊建立後，
   站間未配列不得另生一台車，班表與內部推算都沒有生車權。
2. 同一台車會同時出現在多個車站的倒數裡。相同路線、方向與官方車號的列要合成同一台車的
   逐站 `timeline`，不是各畫一台。沒有官方車號的文湖線／環狀線，沿行進方向的同車到站
   epoch 必然逐站遞增；epoch 回落才是下一台車的邊界。不得再用每一站各自的單段秒門檻生車。
3. 官方車號只是 `vehicleId` 上的顯示標籤，不能決定位置。已認到的號碼若後續變動、消失，或
   同號列出現在物理上不可能到達的遠處，保留原 `vehicleId` 與位置並永久拿掉該趟號碼，畫面
   退回路線縮寫橢圓牌；不得換成新號，也不得為保住號碼把車拖去遠處。抵達終點後，即使原車
   折返且沿用相同車號，也必須等反方向起點倒數出現後建立新的 `vehicleId`。
4. 車一旦建立，後續資料只能更新它。整包讀取失敗、空列、畸形資料、來源版本倒退、單列配對
   失敗、目的地改標及 ETA 前後修訂，都不得刪車、換 ID、複製車或清除跟隨。
5. 每段位置只依該車官方 `timeline` 的出發／到站秒推算。ETA 往回修時，畫面不得倒退；往前修
   只能把新位置當成目標，任何一畫格、15 秒輪詢、頁面停頓或到站 deadline 都不得讓顯示進度
   快過該站間的實際行車秒數。舊的「每 10 秒追一站」與 deadline 強制吸到站規則已完全移除。
6. 一般路線只在車抵達倒數第二站、官方資料確定缺少最後一段時，使用該車已觀測到的官方站間
   節奏補到終點。不得預先用整份靜態班表憑空推完整趟存在性。
7. 小碧潭與新北投支線是兩站單段例外：實測官方資料只有起點倒數，沒有對端到站列，所以使用
   靜態單段行車秒數跑到另一端，抵達即收車。
8. 唯一退場條件是抵達這一趟已知終點。沒有資料齡、缺訊秒數或「太久沒看到」的退場判斷。
9. 班表只在從未取得官方車輛資料，或使用者把模擬時鐘撥離現在時，作為整體備案；班表不得
   決定官方車的存在、身分或退場。
10. 車牌有仍可信且前後一致的 `TrackInfo.TrainNumber` 時顯示該官方欄位；沒有或已發生衝突時
    沿用路線縮寫橢圓牌（文湖線為 `BR`、環狀線為 `Y`）。不得顯示內部 `vehicleId`，也不得把
    無法可靠對回站牌的車廂資料編號冒充車次。

## 實作邊界

- `scripts/trtc_board_ledger.mjs` 先把無車號列依逐站 epoch 的單調區段分群，再由
  `attachOfficialTimelines()` 把同群倒數附加到同一台車；倒數列數不能改變車輛基數。
- `scripts/trtc_official_roster.mjs` 是唯一生命週期 reducer。正常營運只有起點事件可出生，
  既有車沿自己的 `timeline` 保留到 `retireEpoch`；兩輪配對另以實際經過秒數與段秒驗證可達
  距離，官方車號不得略過這道閘門。無車號車先以兩輪重疊的逐站 ETA 辨認身分，再比較沿線
  順序；相鄰站 ETA 差與真正經過的觀測秒相加仍跑不完該段時，必須拒絕配對。
- `worker.js` 把同一份 canonical timeline 寫入持久名冊與回傳 payload；frame key 也包含 timeline，
  避免同 revision 的逐站時間修訂被吃掉。TrackInfo 讀取失敗或本輪組裝失敗時，必須回傳
  D1 最後成功官方名冊作為 `official` hold，不得回空 `outage`；這條規則也適用於剛開頁面、
  前端尚無上一幀的情形。只有 D1 從未建立官方名冊時才能回班表備案。
- `index.html` 的純位置函式負責官方時間軸，顯示層另以 per-vehicle 單調進度消除 ETA 回修造成
  的倒退，並逐段累計 `runBetween()` 限制最大前進距離。資料失敗只標記 hold，不清空最後成功名冊。
- 舊班表校正路徑仍可替班表動畫算 shift，但它的「配不到」只代表那筆 shift 不採用，絕不可
  影響官方名冊。

## 必跑驗收

```sh
node scripts/verify_trtc_official_roster.mjs
node scripts/verify_trtc_official_worker.mjs
node scripts/verify_official_roster_frontend.mjs
```

驗收必須同時包含：

- 同車多站倒數只產生一個 ID，兩個方向各有案例。
- 無車號逐站倒數的 epoch 單調區段只產生一台；下一班起點倒數不得被吞進前車。
- 同號列若在 15 秒內從永安市場跳到丹鳳不得接回；號碼衝突後同一 ID 永久退回路線代號。
- 已認到的車次號遇到後續站牌暫時空白必須沿用；空白不是衝突，只有不同的非空號碼才永久退牌。
- 新開頁面的第一輪 TrackInfo 就失敗時，必須從 D1 讀回已知車、原 `vehicleId` 與已認到的車次；
  只讀不寫、不重發 ID，也不得整批退回班表。
- 當輪只有遠方同號列時，遠方列不得出生；舊車沿既有官方時間線保留，但號碼立即退回路線牌。
- 每台現存車都要帶 `official-board` 出生證據；任何缺少血緣的車讓驗收直接失敗。
- 空輪與長時間缺訊不刪車；目的地與 ETA 修訂不換 ID。
- 站間未配列不出生；反方向即使同車號也用新 ID。
- 一般線補唯一末段；G_XBT／R_XBT 四個方向走單段例外並在對端退場。
- ETA 回修位置不倒退；前修只能在實際段秒上限內前進，互相矛盾的到站秒不得強制吸到站。
- 方向箭頭必須取目前顯示位置的路線切線，不得另讀修訂前的 ETA 時間線；投影向量不得依賴
  目前倍率下的像素距離，zoom 6／7 也要立即指對，不可等放大才自癒；兩個方向都要驗。
- 畫面停頓超過 5 秒後，只能依真正經過秒數往前；不得直接跳到新原始位置。新 ETA 若落在
  已顯示位置後方仍須守住，禁止倒退重設。
- BR 無號多車跨輪必須各自接回原 ID、維持順序，不得交叉或飛奔；兩個方向都要驗。
- BR 兩個方向都必須證明 15 秒內不能把同一 ID 推進完整一站；保存語料中任何跨輪前進都要通過
  「相鄰到站 epoch 差＋真正經過秒 ≥ 該段行車秒」，任何 `coastCycle` 也不得短於該段。
- Chromium 與 WebKit，各跑 360／375／414／768 px 真觸控；車數、命中、溢出與控件碰撞均驗。
- mutation 必須證明任何缺訊 timeout、配不到刪車、終點不停退場或跨方向共用 ID 的改動會轉紅。

## 2026-08-14 驗收結果

- 後端生命週期：40/40 契約、16/16 mutation；保存的尖峰語料 80 輪、九線雙向，ID 無重複、
  不跨方向、退場後不復活，跨輪前進與續推週期零筆違反段秒。
- Worker 持久化：使用 roster schema／D1 key v4，隔離 v3 已產生的 BR 錯誤身分與超短續推週期；空輪保留既有 ID，
  同 revision 修訂採 fresh frame，舊 frame 不覆寫較新時間軸。
- 前端：7/7 純函式 gate、15/15 mutation（包含箭頭與車牌使用同一顯示方向、低倍率固定向量，
  以及長畫格停頓後不倒退、不超過逐段行車秒）。
- 真實瀏覽器：Chromium／WebKit × 360／375／414／768 共 8 組全通過；每組 4/4 合成官方車可畫、
  rAF 到站準時、位置單調、零 pageerror、真觸控可命中、零水平溢出與零控件相交。

若未來資料源契約真的改變，先保存新原始樣本、更新這份契約與正反測試，再動產品；不得先加
推測性的刪車或重新認車規則。
