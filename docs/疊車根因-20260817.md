# 結論

## 現場 A（G 線 312／334）

**判定：假設成立，但「凍在原地」要作精確化。** `312` 的 `source:'census-hold'`、`holdReason:'no-backward'` 只能由 `trtcCensusVehicles` 的站段倒退分支產生：同一 `vehicleId`、同線、同方向、前後皆非 terminal，且新算出的 `to` 落在上一輪 `to` 後方時，整台車改沿用上一輪物件。`334` 則走正常 `source:'census'` 分支。兩車的處理彼此獨立，程式沒有「後車不得追上／穿越被 hold 前車」的群組約束。因此，312 的新官方位置被拒收而 334 仍照自己的官方時間軸前進，最後追及、重疊，正是現有程式允許發生的結果。現場本身亦已被原始碼註解逐號記錄為這個機制（`index.html:4335-4340`）。

「凍在原地」並不必然表示 312 每個動畫畫格都停在同一像素。建車層的 hold 是複製上一輪整個 vehicle（包含舊 timeline），只更新頂層 `arrEpoch/observedEpoch/source/holdReason`（`index.html:4984-4991`）；繪製層會優先沿舊 timeline 內插，timeline 用完後還會續推（`index.html:5171-5205`）。真正會把座標凍在上一畫格的是另一道、同樣只按單一 `line|vehicleId` 運作的顯示守衛（`index.html:5378-5419`）。所以更準確的根因是：**312 被鎖在自己的既有單調軌跡／顯示水位，334 獨立前進；全域沒有列車順序不變量，故 334 可以追到同一位置。**

建車層 `no-backward` 的解除條件是下一輪不再滿足倒退式 `(to - prev.to) * step < 0`。也就是官方 `to` 追平或超過被 hold 的 `prev.to`，或 line／dir 改變，或任一側成為 terminal，就會走正常 `census` 分支（`index.html:4984-5007`；鏡像 `scripts/trtc_census_roster.mjs:199-222`）。因為每輪 held vehicle 又成為下一輪 prior（`index.html:5008-5012`），門檻會固定在被 hold 的舊 `to`，不會自行放寬。

它**可能永久卡住**：這個分支沒有 hold 輪數或期限；只要官方位置永遠落後舊 `to`，就會永久 hold。資料過舊、站碼解不出等其他原因也只是沿用 prior（`index.html:4926-4937`）。即使建車層解除，顯示層仍可能因新 raw progress 低於顯示水位而繼續凍結；只有 raw progress 往前超過水位才恢復推進，另有一個「先 coast 至少 300 秒、再回到非 coast」的特殊重同步例外。原始碼自己明載，沒有該例外時可能凍到退場（`index.html:5396-5424`）。

## 現場 B（BR 155,116／161,182）

**判定：是兩台真車被投影到同一位置，不是同一台被拆成兩台。** Worker 先按完整、原樣的 `TrainNumber` 作 key，只為同一 key 保留最新一列（`worker.js:758-771`），再把每個文湖線 key 原封不動放成一筆 `{no, sys:'br', ...}`（`worker.js:885-897`）。前端也不拆逗號：完整 `no` 直接成為 `cs:<day>:br:<no>`，一個輸入 row 只建一台 vehicle（`index.html:4917-4921,4978-5007`）。鏡像契約更明言文湖線 `no` 是「穩定的車體身分」而非車次（`scripts/trtc_census_roster.mjs:7-16,194-220`）。因此 `155,116` 與 `161,182` 是兩個不同且車廂編號集合互不重疊的編組，程式沒有把 `155,116` 拆成 `155`、`116` 兩台。

程式目前確實存在一個身分正規化缺口：它只比較完整字串，沒有把逗號兩側的車廂編號排序或做集合比對。因此若上游把同一編組另報成 `116,155`、改變空白／分隔符，或同輪送出兩個重疊的車廂集合，現碼會建立兩個 ID。這是結構上可能的另一種 duplicate，但**不是本現場**：本現場兩組編號完全不重疊。

物理算術也指向「兩台真車、位置錯」：班距 120 秒、該段行車 69 秒。若前車在 `t=0` 進段，`t=69` 已離段；後車到 `t=120` 才進段，中間尚有 `120-69=51` 秒。穩定 120 秒班距下兩台真車不可能同時在這個 69 秒站間。這段是**推論、未經執行驗證**；它依題目給定的班距與行車秒，沒有納入臨時停車、追蹤模式或上游時戳異常。但即使有異常，也只會推翻位置／班距假設，不會把兩個互不重疊的實體編組變成同一台車。

B 的位置根因是文湖線沒有可按車號接上的 TrackInfo path：Worker 明確說文湖線 TrackInfo 的 `TrainNumber` 恆空，所以 exact match 得到 `m === undefined`，送給前端的 `dest/path` 皆空（`worker.js:885-897`）。前端在沒有 path 時只用 CarWeightBR 的粗站碼 `stn` 決定 `from/to`，再用 `at + run` 當抵達時刻（`index.html:4944-4965`）。這個來源已知落後 96–265 秒（`index.html:4981-4983`；鏡像 `scripts/trtc_census_roster.mjs:7-13,149-172`）。兩個獨立真車若取得相同／互相矛盾的粗舊錨點，會被獨立投影到相同站段；其後仍沒有跨車順序守衛，遂可畫在同一點。

## 符合產品鐵則的修法方向

1. **把單車水位改成同線同方向的 cohort 順序守衛，不刪車、不倒退。** 改動點應在官方名冊從「逐車獨立 `.map()` 求位置」轉成一輪整批求位置的地方（`index.html:5439-5444`），並只對 `cs:` census vehicle 啟用。先保存上一個可信畫格的前後順序，再對本輪 desired progress 做順序約束：前車被 hold 時，後車只可停在自己的上一顯示水位，不能追越；前車恢復前進後，後車再向前恢復。若修法載入時已經重疊，不把後車往回拉，而是凍住後車、讓前車按既有速度上限先向前分離。這不是調大「疊車門檻」，而是建立目前缺少的「同方向前後次序不可交換」不變量；同段仍可有兩台，只是不准次序相交或進度相等。

2. **建車層不要在倒退時複製整條舊 timeline 繼續 coast。** `index.html:4984-4991`（以及鏡像 `scripts/trtc_census_roster.mjs:199-212`）應把「最新官方觀測」與「最低可顯示水位」分開保存：官方 row 照收，顯示只取 `max(上一顯示水位, 本輪官方水位)`，並交給上項 cohort 守衛。這樣仍完全不倒退，也不會因沿用舊 timeline 而讓 held 車繼續在錯誤軌跡上自行 coast，拉長官方追平時間。

3. **文湖線身分用車廂集合 canonicalize，但不能合併不相交編組。** 在 `worker.js:763-771,885-897` 對 BR 的逗號成員去空白、驗證、排序後產生 canonical consist key；同一集合的不同排列只輸出一台 vehicle，所有原始 observation 仍保留供診斷，取最新合法位置列。只有集合相同才是同一實體車；像 `155,116` 與 `161,182` 的不相交集合必須仍保留兩台。這符合「官方說車在就畫」與「同一實體車不畫兩台」，不是依車數多寡刪車。

上述改法可與正式站班表路徑隔離。官方名冊只有在 `trtcOfficialRosterLive` 成立時才進 `trtcOfficialRenderItems`（`index.html:6268-6279`）；否則繪製直接走 `_tt` 班表的 `freqTrainPosAt`（`index.html:6367-6386`）。資料套用端亦把 census 明確隔在 `CENSUS_ROSTER_ENABLED` 分支，官方模式結尾還會清掉舊看板校正（`index.html:18186-18217`）。因此只在 `cs:` cohort 與 BR ingestion 做上述改動，**不會影響正式站現行純班表位置路徑**。既有 `trtcHeadwayPosition` 雖已有順序概念，但它操作的是班表 `tr`／`ln._trtcBoard`（`index.html:17380-17432`），不能直接當作 census 已有防穿越的證據；應只借用不變量設計，不共用狀態。

# 風險與未確定點

- 本報告是靜態讀碼診斷，沒有啟動 server／瀏覽器，也沒有連 loopback。A 的「312 先被 hold、334 後追及」由題目提供的同畫格 state、明確的 `source/holdReason` 與唯一產生該標記的分支支持；但兩車逐畫格相遇的精確秒序沒有重播。這部分屬**推論、未經執行驗證**；不影響「現碼沒有跨車約束」這個確定結論。
- `source:'census-hold'` 證明建車層拒收站段倒退，不單獨證明該畫格像素完全靜止；舊 timeline 可能繼續移動，顯示層也可能另行凍結。若後續驗收只檢查 source 標籤，會漏掉這兩層差異。
- B 的「兩台真車」判斷依題目明示的文湖線編組語意、兩個不相交車廂集合及現碼完整字串身分規則。若上游其實會在同一時刻把一列四車編組拆成兩個完全不相交的二車 pair 分別回報，則仍需官方 schema 才能排除；現有程式與註解都把每個 pair 當穩定完整車體身分，repo 內沒有相反證據。
- 任何 cohort 修法都必須定義冷啟動時兩車已重疊的初始順序。可用最後可信畫格、官方事件時序或穩定身分 tie-break 建立一次性順序；此後不得交換。不能以「同段車太多」刪車，也不能為分開標記把任何已有顯示水位往後拉。
- BR canonicalization 必須保留原始 `TrainNumber` 與衝突診斷；若只排序字串卻不檢查重複成員、非法 token 或同輪重疊集合，可能把上游資料錯誤靜默合併。它只解身分別名，不會修正本現場的粗舊位置錨點，位置仍需 cohort 順序守衛。
