# 軌島「乘車導覽模式」互動展示原型

給鐵道業者、觀光單位與地方內容伙伴看的展示：旅客掃車廂 QR code，依「這班車」的目的站，
切換地方介紹、必看亮點、推薦路線、在地店家、文化故事與下車後交通。重點是**內容隨目的地切換**，列車位置只是輔助。

這是獨立原型：放在 `prototypes/`（`.assetsignore` 與 `_config.yml` 都已排除，**不會隨正式站部署**），
沒有改動 `index.html` 或任何正式站檔案，也不讀正式站的執行期資源。

委員簡報（現場簡報頁、影片、講稿）見 [PRESENTATION.md](PRESENTATION.md)；一分鐘功能發布影片的企劃與分鏡見 [film/STORYBOARD.md](film/STORYBOARD.md)。

## 怎麼跑

```sh
python3 -m http.server 5178          # 在 repo 根目錄
# 原型：  http://localhost:5178/prototypes/ride-guide/
# 簡報：  http://localhost:5178/prototypes/ride-guide/present.html
```

直接雙擊 `index.html` 用 `file://` 開也可以（資料是 `<script>` 載入，不用 fetch）。

可帶參數直接進到某個狀態：

| 網址 | 結果 |
|---|---|
| `./` | QR 模擬入口 |
| `?line=huadong` | 已帶路線（月台 QR）→ 選班次 |
| `?line=pingxi&train=4816` | 已帶路線＋班次（車廂 QR）→ 直接進旅程 |
| `?line=pingxi&train=4816&dest=shifen&lang=en` | 再加目的站與語言 |
| `#huadong-4528-guangfu-en` | 同上，錨點寫法（Artifact 預覽只傳得進 `#` 錨點） |

班次不存在、目的站不是這班車接下來會停的站時，會提示並讓旅客重選，不會壞掉。

## 三條示範路線

| 路線 | 示範班次 | 導覽站 |
|---|---|---|
| 平溪線 `pingxi` | 4816 八斗子→菁桐、4827 回程 | 十分、平溪、菁桐 |
| 臺東線（花東縱谷）`huadong` | 4528 花蓮→玉里、4543 回程（不停林榮新光，選擇器就不列） | 光復 |
| 海線 `haixian` | 2527 竹南→彰化、2540 回程 | 通霄 |

光復、通霄是隨機抽出的非一級觀光大站（花東、西部各一）。

## 驗收

```sh
node prototypes/ride-guide/verify.mjs
# repo 沒裝 playwright 時：PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node prototypes/ride-guide/verify.mjs
```

跑完整流程（進入示範旅程 → 選十分 → 讀故事 → 改選平溪 → 內容與路線同步切換 → 切英文 → 開地圖 → 回到內容，選擇保留），
再檢查返回鍵、空白內容、重複點擊、網址參數、另外兩條路線、簡報舞台逐幕切換，以及 360／375／414／768／1280px 各寬度：
不橫捲、按鈕觸控高度、逐顆點擊「每顆可見按鈕都有作用」、外部連結、console 錯誤、暗色主題。
截圖在 `_shots/`（不進版控）。

## 資料標示：已查證、OSM、模擬

畫面上每一筆資料都看得出從哪裡來：

- **已查證**：附官方或權威來源連結（新北市觀光旅遊網、文化資產局、區公所、臺鐵、台灣好行等），查核日期 2026-10-01。
- **OSM**：OpenStreetMap 地圖資料（店名、位置、部分營業時間），開放授權（ODbL），未逐一查證。
- **模擬**：官方沒有寫明、但旅客需要的資訊，先用示範值補上：
  - 步行／單車時間＝座標直線距離 × 1.3 ÷ 速度（步行每分鐘 75 公尺、單車 220 公尺）；
  - OSM 沒標營業時間的店家，依店型給一個常見時段；
  - 「建議停留時間」是編輯建議。

  正式版由業者、觀光單位或地圖服務提供真實資料。不模擬評分、評論或店家招牌菜——那會是替真實店家編造內容。

為什麼店家不用 Google 地圖：Google 地圖的服務條款不允許抓取或轉存它的資料；OpenStreetMap 開放授權、標示來源即可使用。
店家依距離排序，不收費、不排名，連鎖超商與速食已排除。

## 哪些是示範資料、哪些沒有串接

**示範資料**

- **班次**：停靠站與時刻由 `build-data.mjs` 從 `data/tra_schedule.json`（臺鐵開放資料逐日時刻表，2026-09-27 抓取，
  適用 2026-09-27～10-10，示範班次皆每日行駛）裁出，班次、方向、停靠站一致。「下一班車」用示範日 2026-10-01 的時刻表。
  改點後重跑產生器即可。
- **列車位置**：依時刻表「手動推進」的示範位置，畫面上一律標「示範」。不是即時位置，沒有速度、沒有誤點。
- **地圖**：軌道線形取自 `data/tra.json`（OpenStreetMap 衍生，ODbL），畫成示意圖並標示出處。
  路線圖、店家圖的點是真實座標，直線連接，標明「不是實際步行路徑」。
- **照片**：Wikimedia Commons（CC0／CC BY／CC BY-SA），授權逐張以 Commons API 核對，作者與授權在圖說與 `img/CREDITS.json`。
  刻意不用招牌顯眼的店家照片。
- **英文**：展示用翻譯，忠於中文來源內容；正式上線需要專人校稿。
- **QR code**：圖樣是示意，不可掃描；`railisland.tw/ride/` 這個網址目前不存在。

**沒有串接**

- 即時列車位置、誤點、月台（TDX／臺鐵即時 API）
- 自動定位（刻意不做：沿途故事由旅客手動點）
- 內容後台：業者、觀光單位、地方伙伴供稿與審核流程
- 真實 QR code 產生，以及 QR 與車廂、班次的對應
- 營業時間這類會變的資訊的定期重新查核
- 登入、訂票、付款、廣告、車廂硬體

## 誠實標示原則

- 未接即時 API，畫面一律標「互動展示／示範班次」，示範徽章用藏青而非警報紅（正式站設計規則）。
- 故事、照片、交通與路線資訊都有來源；查不到又不適合模擬的（例如歷史年份、車站出口）標「待查核」，不自己填。
- 不使用臺鐵或任何單位的標誌，不宣稱已合作或已取得資料授權；不放店家廣告。
