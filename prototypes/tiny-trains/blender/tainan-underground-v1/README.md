# 臺南鐵路地下化　地下結構模型 v1

這個資料夾由一組腳本產生三個檔：地下結構的 3D 網格（`near.mesh.bin.gz`＋`model.json`）和列車高程剖面（`profile.json`）。
世界座標與 9/12 的存檔相同（`x=(lon−120.21295)·111320·cos(22.99681°)`、`y=(lat−22.99681)·111320`，單位公尺，z 向上，地面 z＝0），
給 10/23 對照重播頁用：從上方隔著半透明的殼看地下，殼透明、地板與月台不透明、各部分分成獨立的材質群組，可以個別開關。

這是依 OSM 股道與估計尺寸畫的示意模型，不是竣工測繪。沒有公開數字的尺寸一律標在 `params.json`（每個數字註明查到、二手、OSM 或估計）。

## 數字只有一個來源

所有尺寸（隧道外寬、牆厚、頂板、底板、站體長度、月台長度與邊距、各控制點的高程……）都在 `params.json`，程式裡沒有第二份。
`build.py` 把 `params.json` 原樣放進 `model.json` 的 `params`，`check.py` 再逐欄比對一次。
程式碼裡只有兩類常數：容差與取樣步長（含站體外框的 closing 半徑 `CLOSING_RADIUS_M`，只用來填平股道之間的空隙，不是結構尺寸）；
`check.py` 的檢查規格（車輛限界、坡度上限、取樣間距、9/12 主站網路的四個停車點座標〔只用來對照，見 6.2b〕、
月台兩端外側股道與正線的最小中心距 `PLATFORM_END_MIN_SPACING_M`＝10 m、月台邊緣離軌道中心的合理性上限 `EDGE_GAP_MAX_M`＝0.10 m〔車輛限界半寬之上再多出的量；
不是規範值，只是「邊距再大就不像真的月台」的上限〕；這幾個值只用來檢查，不參與建模）。編組長度不是常數：`check.py` 讀 9/12 重播頁的 `fleet/catalog.json`。
要改尺寸就改 `params.json` 重建；不要改程式。

每個帶 `label` 的欄位都有出處標註，`check.py` 9.1 檢查：`估計` 要有非空的 `basis`（依據），`查到`、`二手` 要有非空的 `sources`（出處代號），引用到的代號都要在 `params.sources` 裡。
`station.lengthM` 與 `station.islands` 標 `估計`、不標 `查到`：數字與配置是查到的（全長 691 m；2 座島式月台、4 股道，北上用第 2 月台、南下用第 1 月台），
但拿標案區段長當箱體長度、以及決定每座月台夾在哪兩條股道之間，是推論；依據與出處寫在各欄位的 `basis`、`sources`。

## 用法

```
python3 build.py --out DIR            # 建模；兩次建置的三個輸出檔 byte-identical
python3 check.py DIR                  # 檢查；項目 1–6、8、9 全 PASS 才回 0，項目 7 只回報，WARN 不影響結束碼
python3 preview.py DIR RENDER_DIR     # 預覽圖（選項：--only 名稱,名稱  --quick  --figs plan,profile,section  --no-blender）
```

- 需要 Python 3、numpy、shapely（建模與檢查）、Pillow（預覽圖）；不要加 `-I`（numpy／shapely 在使用者目錄）。
- `check.py` 會讀專案根目錄的 `memories/tainan-2026-09-12/snapshot.json`（道路與 rails）、`memories/tainan-2026-09-12/fleet/catalog.json`（車輛目錄，6.2 算編組長度）
  和 `prototypes/tiny-trains/blender/tainan-memory-v1/station-footprint.json`（舊站體外框），三者都只讀；
  項目 8 用 git 檢查工作樹，所以要在專案內執行。
- Blender 只用背景模式（`-b`），預覽的取樣數與尺寸見 `preview.py`；`--quick` 取樣與解析度減半，調視角用。
- 輸出資料夾與預覽圖請放在本資料夾之外（建置暫存區）。

## 輸出

- `near.mesh.bin.gz`：Float32 小端、交錯 `[x y z nx ny nz]`（stride 24 B）、不共用頂點、每面一個法線；每種材質一個 drawGroup（`start`、`count` 以頂點為單位）。
  gzip 等級 9、`mtime=0`；`model.json` 的 `sha256` 是解壓後內容的雜湊。預算：三角形 ≤ 60000、gzip ≤ 350000 B、drawGroups ≤ 16。
- `model.json`：欄位照 `memories/tainan-2026-09-12/surroundings/model.json`（單一 `near` LOD、id `tainan-underground`、placement 0,0,0），另有三個擴充欄位：
  `params`（原樣）、`cutouts`（U 槽內側範圍的世界座標 xy 多邊形，地面要挖開的部分）、`footprints`（隧道、站體、U 槽、月台的外框，世界座標 xy、逆時針）；
  U 槽的寬度逐剖面不同，這兩種多邊形沿牆面走，不是等寬的長條。
- `profile.json`：`reference`（參考線折線 xy＋累計長度 d）、`controlPoints`（解析後的 d、z、id、label、basis）、`segments`（每段坡度，‰）、`derived`（站體與月台的 d 範圍、道路交點的 d），
  以及「任一點怎麼算 z」的文字（`howToComputeZ`）：把 (x, y) 投影到參考線得 d，在控制點之間線性內插，沒有豎曲線。

## 給 10/23 重播頁的使用須知

- **停車位置**：臺南站的停車中心用 `profile.json` 的 `derived.platform.centerD`（目前 5348.46），整列車置中：各節車的連結器間距（`catalog.json` 的 `meshes[].pitchM`）首尾相接，整列的中點放在 `centerD`，
  這和 9/12 重播頁 `arrange()` 的排法相同。**不要沿用 9/12 主站網路的四個停車點，也不要沿用 9/12 的停法**：那四個點在月台中心以南約 127 m，目錄裡最長的編組（`e1000`，285.84 m）停在那裡，
  南端會凸出月台約 120 m（`check.py` 6.2b 以 WARN 列出）。置中停靠時 `e1000` 兩端各剩約 7.1 m（6.2 量）；月台長度是估計，縮到比最長編組短，6.2 就會 FAIL。
- **月台用 id 取**：`model.json` 的 `footprints` 裡，月台的 id 是 `platform-{號}`，號＝`params.json` 的 `station.islands[].no`。對應由 6.5 從網格與股道座標量出來，不看名稱字串、不看陣列順序：

  | id | 月台 | 夾在哪兩條股道（OSM way，由西到東） | 側 |
  |---|---|---|---|
  | `platform-2` | 第 2 月台（北上） | 1102288953（西外側）、1102288955（西正線） | 西 |
  | `platform-1` | 第 1 月台（南下） | 1102288954（東正線）、1102288952（東外側） | 東 |

- **洞口處頂板頂在 z＝0**，和地面齊高（洞口處軌道面在 z＝−7，軌道面到頂板頂也是 7 m）。模型維持這樣，不為地面加偏移；洞口附近地面與頂板頂共面的閃爍由重播頁自己處理
  （例如洞口附近把地面壓低一點，或對地面材質用 polygonOffset）。`model.json` 的 `cutouts` 是 U 槽內側要從地面挖開的範圍。
- **殼沒有底面**：隧道與站體的殼（`ug_shell`）只畫頂與兩側外牆，U 槽的牆也沒有封底。這是刻意的：重播頁從上方往下看，底面看不到，畫了只多三角形；看得到的是軌道面高程的地板（`ug_floor`、`ug_trough_floor`）。
  從地下往上看不是這個模型的用途。
- **洞口端牆有兩層面**：端牆是洞口平面上零厚度的封口。`ug_trough` 的材質不是雙面（three.js 預設的 FrontSide，只畫法線朝向相機的面），所以同一個矩形畫兩次，頂點完全相同、法線相反，
  一層朝 U 槽、一層朝隧道，從 U 槽看與從隧道內看都是封住的。兩層共面但法線相反，任何視角只有一層通過背面剔除，不會閃爍。
  **不要把 `ug_trough` 改成雙面**：那會讓 U 槽牆與洞口上方的牆也兩面都畫。`drawGroups[].doubleSided` 照 `model.json` 給的值用。

## 做法

- **參考線與 d**：參考線是西側正線那一串 way 接起來的折線，d 是從南端起算的累計長度。高程剖面 z(d) 只有一個定義（控制點之間線性），
  所有頂點、股道、取樣點的 z 都由它算。控制點同時是網格的分段點，所以網格的高程與剖面在控制點上完全一致。
- **剖面（rung）**：在參考線的每個折點、東側正線折點的投影、控制點與各段端點切垂直於參考線的剖面；折點上取角平分線方向（miter）。
  隧道、U 槽、站體用同一組剖面，接縫不會錯位。OSM 折線不重新取樣，列車走的線與殼的中心線是同一條。
- **隧道**：沿兩條正線的中線，分南北兩段（南洞口到站體南端、站體北端到北洞口）。殼只畫外側面（`ug_shell`），地板（`ug_floor`）畫在內淨寬、軌道面高程。
- **U 槽**：南北引道各一段，寬度逐剖面決定：內淨寬＝該剖面兩股道的中心距（從股道幾何量，約 4.3 m）＋兩側各 `ramps.wallInsetFromTrackM`，外牆再加牆厚 `wallThicknessM`。
  所以 U 槽比隧道窄，而且跟著股道間距變寬或變窄；原因是切換前舊線還在引道旁營運，等寬的 U 槽外牆會壓到舊線。
  地板（`ug_trough_floor`）、內外牆面與牆頂、牆在開口端（接地面）的斷面（`ug_trough`）；牆頂比地面高 `wallTopAboveGroundM`，牆底在軌道面下 `baseBottomBelowTrackM`。
  - **洞口端牆**（`ramps.portalEndWall`）：U 槽比隧道窄，隧道箱體的端面在洞口處會露出來，所以在洞口平面補一層牆：外框是隧道外寬 × （軌道面下 `baseBottomBelowTrackM` 到頂板頂），
    開口是 U 槽內寬 × （軌道面到軌道面上 `soffitAboveTrackM`）。端牆的網格在隧道外緣、U 槽牆的內外面與開口邊切開，邊緣沒有 T 字接點。材質同 U 槽牆（`ug_trough`，不透明）。
    端牆是零厚度的封口，兩邊都要看得到：重播頁用 FrontSide 畫、`ug_trough` 不是雙面，只有法線朝向相機的面會畫，所以每個格子畫兩次，頂點完全相同、法線相反——
    一面朝 U 槽（從引道看到封口），一面朝隧道（從隧道內、或隔著半透明殼從上方看，隧道的端也是封住的）。兩面共面但法線相反，任何視角只有一面通過背面剔除，不會閃爍；
    不另外加厚度，所以不多出新尺寸，也不改變淨空。
  - **洞口上方的牆**（`ramps.portalHeadwall`）：從頂板頂往上到牆頂，厚 `wallThicknessM`，位在端牆平面靠 U 槽的一側，兩側接 U 槽牆。它朝隧道的那一面與端牆在同一個平面，
    但高度範圍上下相接（端牆到頂板頂為止，這一面從頂板頂起），不會同材質共面重疊（共面重疊會閃爍）。
- **站體**：四股道各自外擴「牆距＋牆厚」後取聯集、做閉運算補縫、再與隧道外框聯集，最後用兩個垂直於參考線的平面切出兩端。
  端牆上開孔（等於隧道外矩形），殼的牆面按高度分帶，開孔邊緣沒有 T 字接點。B1 樓板（`ug_b1`）半透明，上下兩面都畫。
- **月台**：兩座島式月台，位在內側兩條正線與外側股道之間，邊緣離軌道中心 `edgeFromTrackCenterM`，頂高 `topAboveTrackM`，
  長度 `lengthM`，沿參考線的中心取站體中心（`station.platform.center`，也就是站體配置範圍的中心）；兩座共用同一個中心。
  外側股道與正線的間距沿站體漸變，月台兩端必須還夠寬才放得下，這由 `check.py` 項目 6.3 在月台兩端量。
  月台的 id 是 `platform-{號}`，號與夾在哪兩股的對應見上面「給 10/23 重播頁的使用須知」的表。
  `edgeFromTrackCenterM` 是建模假設（臺南站實際的邊距查不到）：6.4 要求它落在 [車輛限界半寬 1.6 m, 1.7 m]，而且網格實量到的邊緣離最近股道的中心線要等於它。

## 材質與顏色

顏色是為了隔著半透明殼看地下挑的：殼用偏冷的淡藍灰，B1 用淡綠，才分得出兩層；不透明構件用彼此拉開明度的灰與米色。顏色與不透明度是外觀選擇，不是實測。
drawGroups 的順序就是建議的繪製順序（不透明的先，半透明的 B1、殼最後）。

| 群組 | sRGB | 不透明度 | 雙面 | 內容 |
|---|---|---|---|---|
| `ug_floor` | `#4E5258` | 1.00 | 否 | 隧道與站體地板（軌道面高程，深灰） |
| `ug_trough_floor` | `#6A5F55` | 1.00 | 否 | 引道 U 槽地板（灰褐） |
| `ug_trough` | `#B8B3A8` | 1.00 | 否 | U 槽牆、洞口端牆（正反兩層面）與洞口上方的牆（淺水泥色） |
| `ug_platform` | `#D2C28F` | 1.00 | 否 | 島式月台（米黃） |
| `ug_b1` | `#5FB59A` | 0.34 | 否 | 站體 B1 樓板（淡綠，上下兩面都畫） |
| `ug_shell` | `#7FA6D6` | 0.20 | 是 | 隧道殼與站體殼（淡藍，只畫外側面） |

## 檢查項目（check.py）

| 項目 | 內容 |
|---|---|
| 1 網格 | 數值有限、法線為單位長且與繞序一致、沒有退化三角形、bounds 與實際相符、預算、drawGroups 連續覆蓋、共面重疊稽核（1.5，見下一列）、`params` 與 `params.json` 逐欄相同、網格切面量到的剖面尺寸對 `params`（外寬、牆底、頂板頂、內淨寬、U 槽牆頂、站體底板與頂板、B1 上下緣、月台頂高；U 槽內寬＝實量的兩股中心距＋兩側各 `wallInsetFromTrackM`，內牆到最近股道中心＝`wallInsetFromTrackM`）（1.7） |
| 1.5 共面稽核與具名豁免 | 平面距離 ≤ 0.002 m、面積 > 0.0001 m² 的重疊對（含法線相反的共面對）：不同材質之間要 0；同材質也要 0，唯一的豁免是名叫「洞口端牆正反兩面」的一類——同為 `ug_trough`、法線相反、三個頂點在 1 mm 內相同、都在洞口平面上的對（理由見「做法」的洞口端牆）。豁免的對數與面積逐洞口列出，容差沒有放寬 |
| 1.8 洞口端牆（兩個方向） | 在兩個洞口平面（參考線折點上的角平分面）上，**朝向 U 槽與朝向隧道各量一次**：該方向法線朝向觀看者的 `ug_trough` 三角形的聯集，要蓋住「隧道外框扣掉開口」的面積 ≥ 99%，而且擋住開口的面積 ≤ 1%。洞口上方的牆也量：隧道側（洞口平面上、頂板頂以上）要有朝向隧道的面蓋住 ≥ 99%，U 槽側（離洞口平面一個牆厚）要有朝向 U 槽的面蓋住 ≥ 99%。只算法線朝向觀看者的面，因為重播頁用 FrontSide 畫 |
| 1.9 U 槽沿線掃描 | 每 25 m 切一個剖面（距槽端 3 m 內不量），內牆到最近股道中心＝`wallInsetFromTrackM`；牆面也對 `model.json` 的 `cutouts`、`footprints` 逐剖面比對 |
| 2 淨空 | 四條站內股道與兩條引道股道每 5 m 取樣，車輛限界（軌道中心 ±1.6 m、軌道面上 4.5 m）不碰牆、頂板、月台；回報側向與頂部的最小淨空，並依結構類別分列。垂直面頂緣剛好在軌道面（例如端牆底帶）不算侵入，判斷用的是障礙物所在處的軌道面高程 |
| 3 地板高程 | 地板網格在取樣點的高程與 `profile.json` 的差 ≤ 0.01 m，而且每個取樣點都有地板蓋到 |
| 4 站端位置 | 站體兩端在民族路一段交點與小東路交點之間；回報到兩條路的距離 |
| 5 坡度 | 控制點的 d 另外獨立重算並比對；每段坡度 ≤ 25‰；`segments` 與重算一致 |
| 6.1 月台範圍 | 月台寬度與沿參考線的範圍（網格頂面實量）；長度對 `params`；中心對站體中心（由兩條外側股道的端點在檢查端另外算一次，容差 0.05 m） |
| 6.2 編組停靠 | 各編組整列車的長度＝每節連結器間距 `pitchM` 加總（讀 `fleet/catalog.json`，排法同重播頁 `arrange()`；檢查程式裡沒有長度常數）。以 `profile.json` 的 `derived.platform.centerD` 為停車中心、整列車置中，**兩端離月台兩端的剩餘量都要 ≥ 0**（兩座月台取較小者）；逐編組印兩端剩餘量，並點名最長的編組 |
| 6.2b 9/12 停車點（WARN） | 9/12 主站網路的四個停車點（`STOP_POINTS`）若以最長編組為中心，月台兩端凸出多少，以及各編組以這四點為中心停的最大凸出；有凸出就是 WARN，內文寫明「10/23 重播頁不可直接沿用」。WARN 不影響結束碼，目的是不讓這四個點被當成臺南的停車位置 |
| 6.3 月台兩端間距 | 月台兩端的外側股道與同側正線中心距 ≥ 10 m |
| 6.4 月台邊緣離軌道中心 | 兩段：(1) `params` 的 `edgeFromTrackCenterM` 要落在 [車輛限界半寬 1.6 m，1.6 m＋`EDGE_GAP_MAX_M`＝1.7 m]：下限是車廂不嵌進月台，上限是合理性上限、不是規範值；(2) 獨立量網格：沿每座月台每 1 m 一個剖面，兩座月台 × 兩側的邊緣點到最近那一股的中心線，每一個都要等於 `params` ± 0.005 m。兩段各自會紅：值超出範圍，或網格量到的與 `params` 不一致 |
| 6.5 月台號與 id | footprint 的 id 集合要正好是 `platform-{params.islands[].no}`；每座月台夾在哪兩股由網格與股道座標量出（邊緣點離哪一股最近），要對上 `params` 的 `between`；footprint 外框與該月台頂面重合 ≥ 90%，`no`、`name` 相符。不看名稱字串、不看陣列順序 |
| 7 回報（不判） | U 槽外牆到 9/12 快照 rails 的最近距離（設計原則 ≥ 2.5 m）；站體外框與 9/12 舊站體外框的關係 |
| 8 只動本資料夾 | `git status` 只有本資料夾；`memories` 與 `tainan-memory-v1` 沒有差異；資料夾內沒有多餘檔案 |
| 9.1 出處標註 | 讀 `params.json`：每個帶 `label` 的欄位（目前 35 個）——label 要在 `params.labels` 內；`估計` 要有非空的 `basis`；`查到`、`二手` 要有非空的 `sources`；所有 `sources` 欄位與內文（`basis` 等）提到的 S 代號（S 加數字）都要在 `params.sources` 裡。檢查的是「有沒有標」，不判依據寫得對不對 |

`check.py` 寫成「讀輸出檔重算」：殼的內側面由外側面往內平移牆厚、頂板厚合成，控制點的 d、站體中心（月台中心）、U 槽寬度在檢查端另外算一次，月台邊緣到股道的距離與月台夾在哪兩股也是從網格與股道座標量，不用建模端的內部狀態。
這樣檢查量到的是輸出檔實際的樣子，不是建模時以為的樣子。

## 已知限制與取捨

- 沒有建模的項目列在 `params.notModeled`。
- OSM 折線不重新取樣：折點間距最長數百公尺，折角最大約 6.6°；殼在折點用角平分線接合。取捨是殼的中心線與列車走的線完全一致。
- 洞口處頂板頂與地面齊（軌道面到頂板頂的高度與洞口的高程差相等），所以洞口附近頂板頂與地面共面，閃爍由重播頁自己處理（見「給 10/23 重播頁的使用須知」）；站體頂板的厚度沒有公開數字，所以站體只畫外側頂面，頂部淨空以 B1 樓板下緣與頂板外側面為準。
- 站體的牆比隧道的牆厚，所以在端牆開孔處站體地板比隧道地板每側窄一個牆厚差；兩者高程相同，邊緣有一個小階。
- U 槽比隧道窄（內牆離股道中心 `wallInsetFromTrackM`）之後，外牆離 9/12 快照裡的 rails 仍有一小段不到設計原則的 2.5 m（北端引道較長）；
  `check.py` 項目 7 只回報最近距離與不到 2.5 m 的牆長，不判，數字以輸出為準。對照頁要不要處理，由使用這個模型的頁面決定。
- 相距不到 `D_MERGE`（0.25 m）的剖面會合併，避免 float32 下的極薄三角形；在合併處，U 槽牆面與股道的橫向距離最多差約 1 cm，所以 `check.py` 1.9 的容差是 0.015 m（中段剖面 1.7 是 0.005 m）。
- 兩座月台的寬度不是定值：外側股道與正線的間距沿站體漸變，月台邊緣離軌道中心固定，所以寬度隨之變。
- 月台中心取站體中心，不由外側股道與正線的間距門檻推算：那種做法對門檻非常敏感（東側外側股道與正線的中心距在站體中段只比 10 m 大一點、而且往北很慢地變小，門檻差 0.5 m，中心就移動約 75 m）。
  這個間距現在變成限制月台長度的量：`check.py` 6.3 在月台兩端量並要求 ≥ 10 m，目前東側北端最接近（約 10.2 m），月台再加長一百多公尺就會跌破。
  月台的位置與長度（`station.platform`，標估計）只是示意，不是精準位置。
- 月台長度 300 m 是估計（臺鐵最長的定期編組約 240–290 m，月台長度查不到）。目錄裡最長的編組 `e1000` 是 285.84 m，置中停靠時兩端各剩約 7.1 m，6.2 的結論只在這個長度假設下成立；
  車頭鼻端凸出連結器邊界最多 0.075 m，6.2 沒計入，遠小於剩餘量。
