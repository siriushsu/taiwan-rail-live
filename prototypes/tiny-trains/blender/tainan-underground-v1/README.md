# 臺南鐵路地下化　地下結構模型 v1

這個資料夾由一組腳本產生三個檔：地下結構的 3D 網格（`near.mesh.bin.gz`＋`model.json`）和列車高程剖面（`profile.json`）。
世界座標與 9/12 的存檔相同（`x=(lon−120.21295)·111320·cos(22.99681°)`、`y=(lat−22.99681)·111320`，單位公尺，z 向上，地面 z＝0），
給 10/23 對照重播頁用：從上方隔著半透明的殼看地下，殼透明、地板與月台不透明、各部分分成獨立的材質群組，可以個別開關。

這是依 OSM 股道與估計尺寸畫的示意模型，不是竣工測繪。沒有公開數字的尺寸一律標在 `params.json`（每個數字註明查到、二手、OSM 或估計）。

## 數字只有一個來源

所有尺寸（隧道外寬、牆厚、頂板、底板、站體長度、月台長度與邊距、各控制點的高程……）都在 `params.json`，程式裡沒有第二份。
`build.py` 把 `params.json` 原樣放進 `model.json` 的 `params`，`check.py` 再逐欄比對一次。
程式碼裡只有三類常數：容差與取樣步長（含站體外框的 closing 半徑 `CLOSING_RADIUS_M`，只用來填平股道之間的空隙，不是結構尺寸）；`check.py` 的檢查規格（車輛限界、坡度上限、四個停車點座標、取樣間距）；
以及 `params.json` 只用文字描述的判斷門檻（月台中心取「外側股道與正線中心距 ≥ 10 m」的段，10 m 寫在 `ug_core.py` 的 `PLATFORM_CENTER_MIN_SPACING_M`）。
要改尺寸就改 `params.json` 重建；不要改程式。

## 檔案

| 檔案 | 用途 |
|---|---|
| `params.json` | 全部尺寸、高程控制點、股道（OSM way）清單與標註 |
| `input/alignment.json` | 12 條 way 的座標；`extract_alignment.py` 從 git 取出，`build.py` 的輸入 |
| `extract_alignment.py` | 依 `params.json` 的清單用 `git show` 取出股道座標（只讀 git） |
| `crosscheck.py` | 把 `alignment.json` 與另存的 OSM API 抽取檔逐點比對（只用標準函式庫，要用 `python3 -I` 執行；路徑由命令列給） |
| `build.py` | 建模：產生 `model.json`、`near.mesh.bin.gz`、`profile.json`（`--out` 必填；不在本資料夾留建置輸出） |
| `ug_core.py` | 座標、參考線與剖面座標、高程剖面、站體與月台的配置（只計算，不寫檔） |
| `ug_mesh.py` | 隧道、U 槽、站體、月台的網格 |
| `ug_materials.py` | 材質表（顏色在下面） |
| `ug_out.py` | 讀輸出檔的小工具，`check.py` 與預覽共用（刻意不 import 建模端的程式） |
| `check.py` | 檢查輸出（項目 1–8，見下） |
| `preview.py`、`preview_blender.py`、`preview_figs.py` | 預覽圖：Blender 背景模式算圖，平面、縱剖面、橫剖面用 Pillow 畫 |

## 用法

```
python3 build.py --out DIR            # 建模；兩次建置的三個輸出檔 byte-identical
python3 check.py DIR                  # 檢查；項目 1–6、8 全 PASS 才回 0，項目 7 只回報
python3 preview.py DIR RENDER_DIR     # 預覽圖（選項：--only 名稱,名稱  --quick  --figs plan,profile,section  --no-blender）
```

- 需要 Python 3、numpy、shapely（建模與檢查）、Pillow（預覽圖）；不要加 `-I`（numpy／shapely 在使用者目錄）。
- `check.py` 會讀專案根目錄的 `memories/tainan-2026-09-12/snapshot.json`（道路與 rails）和 `prototypes/tiny-trains/blender/tainan-memory-v1/station-footprint.json`（舊站體外框），兩者都只讀；
  項目 8 用 git 檢查工作樹，所以要在專案內執行。
- Blender 只用背景模式（`-b`），預覽的取樣數與尺寸見 `preview.py`；`--quick` 取樣與解析度減半，調視角用。
- 輸出資料夾與預覽圖請放在本資料夾之外（建置暫存區）。

## 輸出

- `near.mesh.bin.gz`：Float32 小端、交錯 `[x y z nx ny nz]`（stride 24 B）、不共用頂點、每面一個法線；每種材質一個 drawGroup（`start`、`count` 以頂點為單位）。
  gzip 等級 9、`mtime=0`；`model.json` 的 `sha256` 是解壓後內容的雜湊。預算：三角形 ≤ 60000、gzip ≤ 350000 B、drawGroups ≤ 16。
- `model.json`：欄位照 `memories/tainan-2026-09-12/surroundings/model.json`（單一 `near` LOD、id `tainan-underground`、placement 0,0,0），另有三個擴充欄位：
  `params`（原樣）、`cutouts`（U 槽內側範圍的世界座標 xy 多邊形，地面要挖開的部分）、`footprints`（隧道、站體、U 槽、月台的外框，世界座標 xy、逆時針）。
- `profile.json`：`reference`（參考線折線 xy＋累計長度 d）、`controlPoints`（解析後的 d、z、id、label、basis）、`segments`（每段坡度，‰）、`derived`（站體與月台的 d 範圍、道路交點的 d），
  以及「任一點怎麼算 z」的文字（`howToComputeZ`）：把 (x, y) 投影到參考線得 d，在控制點之間線性內插，沒有豎曲線。

## 做法

- **參考線與 d**：參考線是西側正線那一串 way 接起來的折線，d 是從南端起算的累計長度。高程剖面 z(d) 只有一個定義（控制點之間線性），
  所有頂點、股道、取樣點的 z 都由它算。控制點同時是網格的分段點，所以網格的高程與剖面在控制點上完全一致。
- **剖面（rung）**：在參考線的每個折點、東側正線折點的投影、控制點與各段端點切垂直於參考線的剖面；折點上取角平分線方向（miter）。
  隧道、U 槽、站體用同一組剖面，接縫不會錯位。OSM 折線不重新取樣，列車走的線與殼的中心線是同一條。
- **隧道**：沿兩條正線的中線，分南北兩段（南洞口到站體南端、站體北端到北洞口）。殼只畫外側面（`ug_shell`），地板（`ug_floor`）畫在內淨寬、軌道面高程。
- **U 槽**：南北引道各一段。地板（`ug_trough_floor`）、內外牆面、牆頂、兩端面、洞口上方的牆（`ug_trough`）；牆頂比地面高 `wallTopAboveGroundM`，牆底在軌道面下 `baseBottomBelowTrackM`。
- **站體**：四股道各自外擴「牆距＋牆厚」後取聯集、做閉運算補縫、再與隧道外框聯集，最後用兩個垂直於參考線的平面切出兩端。
  端牆上開孔（等於隧道外矩形），殼的牆面按高度分帶，開孔邊緣沒有 T 字接點。B1 樓板（`ug_b1`）半透明，上下兩面都畫。
- **月台**：兩座島式月台，位在內側兩條正線與外側股道之間，邊緣離軌道中心 `edgeFromTrackCenterM`，頂高 `topAboveTrackM`，
  長度 `lengthM`，沿參考線以「兩側外側股道與正線中心距夠大的段」的重疊部分中點為中心；兩座共用同一個中心。

## 材質與顏色

顏色是為了隔著半透明殼看地下挑的：殼用偏冷的淡藍灰，B1 用淡綠，才分得出兩層；不透明構件用彼此拉開明度的灰與米色。顏色與不透明度是外觀選擇，不是實測。
drawGroups 的順序就是建議的繪製順序（不透明的先，半透明的 B1、殼最後）。

| 群組 | sRGB | 不透明度 | 雙面 | 內容 |
|---|---|---|---|---|
| `ug_floor` | `#4E5258` | 1.00 | 否 | 隧道與站體地板（軌道面高程，深灰） |
| `ug_trough_floor` | `#6A5F55` | 1.00 | 否 | 引道 U 槽地板（灰褐） |
| `ug_trough` | `#B8B3A8` | 1.00 | 否 | U 槽牆與洞口上方的牆（淺水泥色） |
| `ug_platform` | `#D2C28F` | 1.00 | 否 | 島式月台（米黃） |
| `ug_b1` | `#5FB59A` | 0.34 | 否 | 站體 B1 樓板（淡綠，上下兩面都畫） |
| `ug_shell` | `#7FA6D6` | 0.20 | 是 | 隧道殼與站體殼（淡藍，只畫外側面） |

## 檢查項目（check.py）

| 項目 | 內容 |
|---|---|
| 1 網格 | 數值有限、法線為單位長且與繞序一致、沒有退化三角形、bounds 與實際相符、預算、drawGroups 連續覆蓋、不同材質之間共面重疊為 0、`params` 與 `params.json` 逐欄相同、網格切面量到的剖面尺寸對 `params`（外寬、牆底、頂板頂、內淨寬、U 槽牆頂、站體底板與頂板、B1 上下緣、月台頂高） |
| 2 淨空 | 四條站內股道與兩條引道股道每 5 m 取樣，車輛限界（軌道中心 ±1.6 m、軌道面上 4.5 m）不碰牆、頂板、月台；回報側向與頂部的最小淨空，並依結構類別分列 |
| 3 地板高程 | 地板網格在取樣點的高程與 `profile.json` 的差 ≤ 0.01 m，而且每個取樣點都有地板蓋到 |
| 4 站端位置 | 站體兩端在民族路一段交點與小東路交點之間；回報到兩條路的距離 |
| 5 坡度 | 控制點的 d 另外獨立重算並比對；每段坡度 ≤ 25‰；`segments` 與重算一致 |
| 6 月台 | 月台寬度與沿參考線的範圍（網格頂面實量）；長度對 `params`，中心另外獨立重算（外側股道取樣、投影到參考線）並比對；四個停車點與月台的相對位置（回報） |
| 7 回報（不判） | U 槽外牆到 9/12 快照 rails 的最近距離（設計原則 ≥ 2.5 m）；站體外框與 9/12 舊站體外框的關係 |
| 8 只動本資料夾 | `git status` 只有本資料夾；`memories` 與 `tainan-memory-v1` 沒有差異；資料夾內沒有多餘檔案 |

`check.py` 寫成「讀輸出檔重算」：殼的內側面由外側面往內平移牆厚、頂板厚合成，控制點的 d、月台中心在檢查端另外算一次，不用建模端的內部狀態。
這樣檢查量到的是輸出檔實際的樣子，不是建模時以為的樣子。

## 已知限制與取捨

- 沒有建模的項目列在 `params.notModeled`。
- OSM 折線不重新取樣：折點間距最長數百公尺，折角最大約 6.6°；殼在折點用角平分線接合。取捨是殼的中心線與列車走的線完全一致。
- 洞口處頂板頂與地面齊（軌道面到頂板頂的高度與洞口的高程差相等）；站體頂板的厚度沒有公開數字，所以站體只畫外側頂面，頂部淨空以 B1 樓板下緣與頂板外側面為準。
- 站體的牆比隧道的牆厚，所以在端牆開孔處站體地板比隧道地板每側窄一個牆厚差；兩者高程相同，邊緣有一個小階。
- U 槽外牆離 9/12 快照裡的 rails 很近（設計原則是 ≥ 2.5 m）；`check.py` 項目 7 只回報最近距離與不到 2.5 m 的牆長，不判。對照頁要不要處理，由使用這個模型的頁面決定。
- 兩座月台的寬度不是定值：外側股道與正線的間距沿站體漸變，月台邊緣離軌道中心固定，所以寬度隨之變。
- 月台中心對「中心距 ≥ 門檻」的門檻非常敏感：東側外側股道與正線的中心距在站體中段只比 10 m 大一點，而且很慢地變小（d≈5140 約 11.4 m、d≈5565 約 10.0 m），所以重疊段的端點會隨門檻或量法移動幾十公尺。門檻取 9.5、10、10.5、11 m 時，中心 d 約為 5359、5345、5270、5194。月台位置（以及 `check.py` 項目 6.2 的停車點相對位置）只能當成「放在站體中段」的示意，不是精準位置；要固定位置，就在 `params.json` 直接給月台中心的 d，並讓 `ug_core.py` 讀它。
